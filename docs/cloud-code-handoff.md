## 読み取りと再開

保存先は非公開の `R2 Standard` バケット `public-interest-lens-raw`、検索索引は `D1` データベース `public-interest-lens-index`（識別子 `edc7440c-43b4-4e12-aa67-867efe0ff167`）です。`r2.dev`による公開は無効で、カスタムドメインも接続していません。この識別子は認証情報ではなく、受け手は別途許可されたアカウントの権限を確認する必要があります。

1. `python -m scripts.cloudflare_material_transfer --help` と `python -m scripts.cloudflare_material_index --help` で、既存入口と必須引数を確認します。
2. ローカルの原資料・移行計画・受領記録は非公開の `.local` 内へ置きます。認証情報をコマンド・ソース・ログへ貼り付けません。既定の処理は読取りのみです。
3. 移行の再開は本線が対象・認証名義・単一の書込み担当・前回終了状態を確認した後に行います。受領記録だけを信頼して省略せず、既存ファイルを全文ハッシュで再検証します。別担当の移行を重ねません。
4. `cloudflare_material_index` は完全に検証済みの受領記録だけから安全な索引候補を生成します。進行中・失敗・宛先不一致を拒否し、索引データベースへの書込み機能は持ちません。索引への反映は本線の別工程です。
5. 公開索引が確定した後も、その参照先を自動取得したり、原資料の公開設定を変更したりしません。データベースの読取り権限・認証・接続先は人間が承認した環境で確認します。

既存の標準認証は、長時間の転送で期限切れになる場合があります。転送入口は期限を確認し、期限切れの場合だけ既存の `Wrangler whoami --json` による非対話更新を使います。対象アカウント、更新後の期限、権限範囲を確認できなければ停止します。別の認証ファイルや、新しいログイン・権限追加へ勝手に切り替えません。

## 索引を再生成・照合する入口

次のコマンドは認証済みの指定データベースを読み、既存行と一致する行を除いた不足行だけの投入候補を保存します。データベースへは書き込みません。受領記録とアカウントは、実行担当が承認済みの対象へ置き換えてください。

```sh
python -m scripts.cloudflare_material_index --receipt .local/transfer-receipt.json --account-id <対象アカウントID> --bucket public-interest-lens-raw --database-name public-interest-lens-index --read-existing --sql-output .local/material-index.sql --output .local/material-index-packet.json --write
```

不足行の反映は、準備した内容と保存先を確認した本線が、既存の公式手順で行います。承認なく実行しません。

```sh
wrangler d1 execute public-interest-lens-index --remote --file .local/material-index.sql --json
```

反映後の全行照合と、公開用の許可列だけの索引の再生成は次の入口です。索引と原本内容の検証状態を分けます。

```sh
python -m scripts.cloudflare_material_index --receipt .local/transfer-receipt.json --account-id <対象アカウントID> --bucket public-interest-lens-raw --database-name public-interest-lens-index --verify-index --output .local/material-index-verification.json --write
python -m scripts.cloudflare_material_index --receipt .local/transfer-receipt.json --account-id <対象アカウントID> --bucket public-interest-lens-raw --public-manifest-output data/cloudflare/materials.json --write
```
