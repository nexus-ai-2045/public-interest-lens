# クラウド実装担当への引き継ぎ

## 目的と現在の停止線

この文書は公開ソースの再開方法です。認証情報、端末の保存先、非公開受領記録、原資料全文は含めません。クラウドの実装担当は目的正本の `PROJECT_SSOT.md`、データ区分の `data/README.md`、本書と運用手順を読み、取得・内容検証・採点・サイト配信を別々に扱います。

公開カタログをクラウドの索引データベースへ写した本線の照合結果は、16テーブル・244行の全値一致です。原資料の物体保存先への移行は実行中であり、全件完了ではありません。原資料の内容は `unverified`、実在人物の採点は0件、サイト配信は未実施のままです。

## 公開候補の索引と非公開資料

原資料の保存先は非公開を維持します。公開候補の `data/cloudflare/materials.json` は、本線が完全な移行受領記録を回収した後に作成します。ファイルが存在しない段階で、計画件数や部分成功を検証済み索引に置き換えません。

公開候補はハッシュ、物体キー、バイト数、媒体形式、出現識別子、公式資料の参照先、観測時刻、`contentVerification=unverified` に限定します。認証・アカウント識別子・端末パス・原資料全文・私的な題名や目的は含めません。ハッシュの一致は内容の正しさや公開権利の確認ではありません。

## 読み取りと再開

1. `python -m scripts.cloudflare_material_transfer --help` と `python -m scripts.cloudflare_material_index --help` で、既存入口と必須引数を確認します。
2. ローカルの原資料・移行計画・受領記録は非公開の `.local` 内へ置きます。認証情報をコマンド・ソース・ログへ貼り付けません。既定の処理は読取りのみです。
3. 移行の再開は本線が対象・認証名義・単一の書込み担当・前回終了状態を確認した後に行います。受領記録だけを信頼して省略せず、既存物体を全文ハッシュで再検証します。別担当の移行を重ねません。
4. `cloudflare_material_index` は完全に検証済みの受領記録だけから安全な索引候補を生成します。進行中・失敗・宛先不一致を拒否し、索引データベースへの書込み機能は持ちません。索引への反映は本線の別工程です。
5. 公開索引が確定した後も、その参照先を自動取得したり、原資料の公開設定を変更したりしません。データベースの読取り権限・認証・接続先は人間が承認した環境で確認します。

## 未確認と担当

本線が移行の終端、物体と出現の全件照合、索引反映の結果、公開候補の内容・権利を回収します。実装担当は画面・読取り接続・テストの差分と残務を返します。原資料の内容検証、人物照合、政策影響の独立検証、採点、サイト配信、設定・認証・課金の変更は本書から承認されません。

転送失敗時は別の並列処理が終了するまで待ち、受領記録の一覧を全送信件数と読み替えません。不存在確認と送信は非原子的なので、移行先への別書込み担当を置きません。矛盾する既存物体や索引は上書きで解消せず本線へ戻します。

## 引き継ぎの受入条件

対象コミット、比較元、公開索引の有無と検証状態、非公開資料を含まない範囲、未確認事項、担当者、停止線を受領側が確認して初めて引き継ぎ成立とします。送信・起動・部分成功を移行や製品の完成と扱いません。
