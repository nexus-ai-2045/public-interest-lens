# フィードバックループ（5段）

更新日：2026-10-17。小さいループほど速く回り、上の段ほど「ループそのもの」を直す。各段に「何を測るか」「どこに記録するか」「何を直すか」「改善の選択肢」を置く。改善の選択肢は、いま採っていない手も消さずに残す。

| 段 | 周期 | 回すもの | 記録 | 直す対象 |
|---|---|---|---|---|
| L1 変更 | 変更ごと（分） | `python3 scripts/preflight.py`（マージ前は `--smoke`）、`python3 -m pytest -q tests`、`npm test`（app）、push 前の個人名義検査 | コミット | コード・データ |
| L2 PR | PR ごと（時間） | 自動レビュー、CI（赤ならローカルの pytest で代わり）、出典チェック、`scripts/roadmap_check.py` | PR の本文とレビュー | PR の中身、ロードマップの自分の行 |
| L3 定期更新 | 週2回（月・木 3:00 JST、R23） | `scripts/daily_update.py --all`（取得→再計算→出典チェック→議員ページ→検査→片付け） | `.local/daily-update/<日付>/report.md` と自動更新の PR | 取得の失敗、出典の不一致、外した法律 |
| L4 判断の型 | 不一致や訂正が出るたび（週） | AI 2系統の不一致・誤りの型、訂正窓口の申し立て | `docs/学習記録/`（判断の型ごとに1ファイル）、`docs/corrections.md` の Issue | 判定ルール・プロンプト・対応表（ルールの新版として） |
| L5 メタ | 節目（ゴール条件の1つが変わったとき、月1） | ロードマップと ADR の見直し、どのループが回っていないかの点検 | `docs/ロードマップ.md` の更新、新しい ADR、この表の「改善の記録」 | ループそのもの（段の追加・周期・記録場所）、方針 |

## 各段の詳細

### L1 変更
- 測る：テストの成否、個人名義検査の成否。
- 改善の選択肢：遅いテストに印を付けて分ける／pre-commit フックにする（`--no-verify` は使わない）。

### L2 PR
- 測る：CI の成否、レビューの指摘数、`roadmap_check.py` の残り件数。
- 既知のエラー：GitHub Actions は課金不足で赤になりがち → ローカルで pytest を回して代わりにする。PR が main より遅れていると「verify is expected」でマージできない → main を取り込んで push し直す。
- 改善の選択肢：同じ指摘が2回出たら検査（テスト）にする。

### L3 毎朝
- 測る：取得できた取得元の数、再計算した本数、出典チェックで外した本数、額つき・理由つきの本数。
- 無限ループを防ぐ：失敗した取得はその日は飛ばす（再試行しない）。外した法律は翌朝に照合し直すだけ。
- 改善の選択肢：取得元の許可（`*.go.jp`、R16）／件数の変化が大きい日は PR を下書きのまま止める。

### L4 判断の型
- 測る：2系統の不一致率、第3の判定者の決着率、訂正の採用率。
- 記録の形：1ファイルに「誤りの型」「件数」「ルールの変更」「変更後の不一致率」を追記する（例 `docs/学習記録/ai-field-v1.md`）。
- 改善の選択肢：系統2のモデルを替えて独立性を上げる／不一致の多い分野だけ第3の判定者を Opus にする。

### L5 メタ
- 測る：ロードマップの「済」の割合、G1〜G6 の達成数、L1〜L4 のどれかが2週続けて記録なしになっていないか。
- 改善の選択肢：段の周期を変える／記録先を1か所に寄せる／回っていない段を自動化する（定期実行）。
