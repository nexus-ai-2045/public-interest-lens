# 政党交付金の使途等報告書（総務省・索引 SK）

政党交付金の「どこから来て、どう使われたか」を、党本部と各政党支部の報告書（総務省が公表）から取り、支部の代表者（議員が多い）に結ぶ。**点数には使わない**。印は事実の記録で、不正とは書かない。

## 範囲

- 取り込んだ年分：令和7年（2025年）分。索引ページ `SK20260925` の `TK/` 配下の PDF 1,167件（党本部・総支部・支部）。令和3〜6年分（SK20220930・SK20230929・SK20240927・SK20250926）は同じ手順で取れるが未実施。
- 総務省の索引（`data/acquired/political-funds/index.csv`、`python3 scripts/political_funds.py crawl --source 総務省`）には、SK のほかに SS（政治資金団体など）と SA・SD（党本部の定期公表）があり、政党支部の収支報告書（SL）と国会議員関係政治団体（SC）の索引ページは今の総務省トップに無い（SC は別の入口で取った 1,649件を [政治資金収支報告書.md](政治資金収支報告書.md) で扱っている）。SL・SF・県選管分の残りは未取得。

## 手順

```
python3 scripts/party_subsidy.py urls   --page SK20260925   # PDF の URL 一覧
（curl で取得 → pdftoppm で1〜3頁を画像化: scripts/party_subsidy.py render）
独立した2つの AI の読み手（A・B）が各 PDF の画像を読み、.local/party-subsidy/line-{a,b}/<PDF の幹>.json に書く
（食い違いは3つ目の読み手 C が line-c/ に。A か B と一致したものだけ採る）
python3 scripts/party_subsidy.py build --page SK20260925    # 突き合わせ・算術の検査・議員に結ぶ
```

読み手の JSON は、表紙の名称・代表者・区分、その2（収支の状況）の①〜⑧と交付元、その3（支出項目別）の費目の金額。**事務所の住所・会計責任者・事務担当者・電話は読まず、出力にも残さない。**

## 採る基準

1. A・B の読みが（名称・代表者・区分・金額・費目の合計まで）一致したものだけ採る。食い違いは C が片方と一致したときだけ採る。どちらでもなければ不採用（空欄のまま）。
2. 算術で検べる：③＝④＋⑤、①−③＋②−⑧＝0（報告書の備考欄の式）、費目の和＝合計。式の項がそろっているものだけ検べ、食い違えば不採用。頁が欠けた PDF（党本部の分冊など）は欠けた式を飛ばし、`検査` を「一部の頁のみ」とする。
3. 交付元の一覧は続きの頁があり不完全なことがあるので、A・B が一致したときだけ「主な交付元」に入れる。

## 議員への結び

支部の代表者の氏名が `data/derived/person-ids/persons.csv` で1人に決まるときだけ人物IDを付ける。衆院の選挙区支部（○○県第十九選挙区支部）は選挙区も合わせて `結びの確度` を「氏名と選挙区が一致」にし、それ以外は「氏名のみ一致」（同姓同名の別人の可能性が残る）。結べなければ代表者は「（未照合）」とし、氏名は出さない。

## 出力

`data/derived/party-subsidy/branch-subsidy-2025.csv`（支部ごと：交付金総額・前年末基金残高・交付金による支出・本年末基金残高・費目別支出・主な交付元・原本 PDF の URL）と `summary-2025.json`。

## 限界

- 令和7年分のうち読み取りが済んだ分だけ。不採用の件数は `summary` の「採用経路の内訳」に出る。
- 党本部（自民党・公明党など）は様式が違い、分冊された PDF がある。支部単位の式に当たらない頁は null のままで、本部の合計は今回は作っていない。
- 交付金の流れ（本部→支部）は、支部側の報告の「交付元」から見たもの。本部側の「支部への交付」との突き合わせは未実施。
