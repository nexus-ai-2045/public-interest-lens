# 政治資金収支報告書の取り込み

議員・党と団体（業界団体・宗教団体・後援会・企業・労働組合）の関係を、収支報告書という一次資料で残す。
責任の配り方の見直し（`/mnt/project-files/analysis/責任の配り方_見直し案_2026-10-24.md`）で使う材料で、**点数にはまだ反映しない**（配り方の決定待ち）。

## 取る範囲

| 出典 | 中身 | 公表期間 | 始点 |
|---|---|---|---|
| 総務省（中央分） | 政党本部・政治資金団体・国会議員関係政治団体などの報告書 | 3年 | `data/acquired/political-funds/sources.csv` |
| 47都道府県の選管 | 県に届け出た政治団体（議員の支部・後援会の多く） | 各県3年 | 同上 |
| 国立国会図書館 WARP | 公表期間が切れた総務省・県のページの保存版 | 保存された年分 | 同上 |

## 頻度

報告書は年1回（総務省はおおむね11月末）の公表なので、**月1回**取る（ねくさんの指示 2026-10-23。毎朝は取らない）。
毎朝の自動更新 `daily_update.py --fetch` の中で `political_funds.py all --monthly` を呼び、前回の取得から28日たっていなければ通信する段（crawl・download）を飛ばし、手元のデータの段（extract 以降）だけ回す（公表期間の切れた個人の支払先を毎日伏せ直すため）。
取得は1回あたり40分で打ち切り（20件ごとに取得の記録を書き、自動更新の1段の上限1時間に収める）、まだ試していない PDF が残っている間は月次の記録（`last-fetch.txt`）を進めないので、翌朝に続きを取る。
1回目の全件取得は時間を決めずに `python3 scripts/political_funds.py all` で回す。

## 段

```
crawl → download → extract → parse（系統A）→ compare（系統A×系統B）→ link（人物ID）
```

- **crawl**：sources.csv の始点から、同じホストの同じパスの下の HTML をたどり、PDF の一覧 `index.csv` を作る（年分・団体区分・団体名・関係議員名は索引の見出しとリンク文字から。親ページの年分・団体区分は子ページへ引き継ぐ）。人物IDに結ぶ根拠になる索引ページの HTML も外部資料として保管し、資料IDを一覧に残す。
- **roster**：総務省「政治団体名簿」（なるほど!政治資金）の「現職国会議員の資金管理団体一覧」「現職国会議員の国会議員関係政治団体一覧」（文字の PDF、総務大臣届出と都道府県選管届出の両方）を表として読み、`member-groups.csv`（氏名・届出上の氏名・院・選挙区・届出先・団体名・区分・名簿・資料ID）にする。総務省の索引ページには関係議員名が無いので、link はこの対応表で「届出先（総務省の索引は総務大臣、県の索引は県名）×団体名」から議員を引き、議員が1人に決まるときだけ使う。団体名はかっこ書き（代表者名・略称）を落として照合する（索引と名簿で代表者名の字が違うことがある）。名簿は現職議員だけなので、元議員の団体は結ばない。名簿が更新されたら `ROSTERS` に足す。
- **download**：未取得、または登録原本を検証できない PDF を対象に、指定した非公開保管庫へ `register_once` で登録する（原本は Git に入れない）。保持は `--keep all` のみで、`image`／`none` の保持例外は未採用のため通信前に拒否する。容量が足りないときは `--storage` で容量のある保管庫を指定し、空きの不足時は取得を停止する。登録後は既存の外部資料検証でrecord・原本・URL・sha256・byte数・観測日時を読み戻し、成功した後だけ作業copyを消す。失敗時は取得日時・hashとcopyを残し、次の試行で同じcopyを使える。旧manifestの取得済み表示だけを根拠に未登録・欠落・破損を読み飛ばさない。壊れた登録記録を無断で上書きせず、検証できない間は失敗とする。取得の記録は `manifest.csv`。
- **extract**：`pdftotext -layout`。1ページ80字未満は画像 PDF として `.local/political-funds/ocr-queue.csv` へ。OCR の結果を `.local/political-funds/ocr/<sha256>.txt` に置けば以後はそれを読む。`pdftotext` が失敗したものは「文字抽出の失敗」として記録だけし、結果を保存せず次回試し直す。
- **parse**：系統A（規則）。「法人その他の団体からの寄附」「政治団体からの寄附」「政治資金パーティー対価支払者」「寄附・交付金（支出）」の節から、相手方・金額・年月日・頁を拾う。
- **compare**：読み手が明示した有効な相手方種別は保持し、名前の推測で不一致を一致へ変えない。個人の伏字は種別の照合と別に維持する。系統B（別の読み手。Haiku が原本の文字か画像を読み、`.local/political-funds/line-b/<sha256>.json` に `{"関係議員名": 報告書から独立に判定した議員名, "根拠": 表紙の代表者・資金管理団体の届出など, "行": [{区分,費目,相手方,相手方種別,金額,年月日,頁}]}` を書く。区分は「受けた寄附・パーティー対価・出した寄附・支出」、費目は支出なら人件費・光熱水費・備品・消耗品費・事務所費・組織活動費・選挙関係費・機関紙誌の発行その他の事業費・調査研究費・その他の経費のどれか（必須）、出した寄附なら「寄附・交付金」。支出で費目が無いものは入力不備として一致させない）と、区分・相手方・金額・年月日がそろった行だけを採る。食い違いは `.local/political-funds/disagreements.csv`（照合前の行で個人名を含みうるので Git に入れない）。
- **画像の報告書**：ほぼ全部が紙をスキャンした画像で、規則（pdftotext）では読めない。`pages` で各頁の左上の様式番号（その○）を tesseract で読み、表紙と寄附・パーティー・支出の内訳の頁（`pages_to_read`）だけを画像にする。それを2つの AI の読み手（Haiku を別々に2回）が独立に読み、`line-a-ai/` と `line-b/` に同じ形の JSON を書く。両方が一致した行だけを採る。食い違った行のある頁だけを3つ目の読み手（Sonnet、`line-c/`）が読み、C が A か B の片方と一致した行だけを足す（`tie_break`。独立した2つの読みの一致という基準は変えない）。名前の表記ゆれ（㈱と(株)、異体字）は `reader_name` でそろえてから突き合わせる。
- **link**：2系統の AI の読み手が同じ議員を判定し、候補がちょうど1人のときだけ `data/derived/person-ids/persons.csv` の人物IDに結ぶ。索引の「関係議員名」（無ければ roster の対応表で引いた議員）があるときは、それとも一致することを必須とする。索引と片方の読み手だけの一致では採らない。読み手の食い違い・どちらかの未回答・同姓同名は結ばず、理由を「帰属の照合」に残す。結果は `data/derived/political-funds/relations.csv`。過去の関係・議員別集計は、この基準と2つの読み手の入力を使ってlinkから作り直すまで、今回の修復で検証済みとは扱わない。
- **団体名キー**：relations.csv の「団体名キー」は `scripts/org_names.py` の `org_key()`（NFKC・空白の削除・法人格の除去）で作る。相手方が個人の行は空。審議会の団体の帳簿（`build_org_ledger.py`）も同じ関数で団体名をそろえて結ぶ。略称の展開や支部の統合はしない。

## 個人の扱い

- 寄附者・パーティー券購入者が個人のときは、氏名・住所・職業をどの出力にも残さない（「（個人）」と金額だけ）。
- 支払先（支出・寄附の支出先）は個人でも報告書の公表どおりに名前を出す（ねくさん 2026-10-23）。住所は出さず、原本 PDF へのリンクを付ける。
- 公表期間（総務省は3年）が終わった年の個人の支払先は、扱いが決まるまで「（個人）」に伏せる（`public_name`）。
- 議員（公人）と団体・法人は名前を残す。

## 議員ごとのお金の使い方

`link` の段で `data/derived/political-funds/spending-by-member.json` を作る。人物IDに結んだ関係団体（資金管理団体・政党支部・後援会など）の支出を、議員・年分・費目（人件費・光熱水費・備品・消耗品費・事務所費・組織活動費・選挙関係費・機関紙誌の発行その他の事業費・調査研究費・寄附・交付金・その他の経費）ごとに合計し、主な支払先（上位20、出典 PDF つき）を並べる。/members の議員ページに出すための形で、点数には使わない。

### 支払いの偏り

議員ごとに、名前の分かる支払先（伏せた個人は除く）への支出で、上位1・上位3の割合、HHI、複数年・複数の関連団体にまたがる支払先を出す。
合計100万円以上で、次のどれかに当たれば「偏りがある」の印を付ける：1つの支払先が30%以上／上位3つで60%以上／同じ支払先に3年分以上かつ20%以上。
印は事実の記録で、不正とは書かない。親族企業・秘書が関わる会社かどうかは、登記・報告書などの一次資料で確かめたものだけを別に記す（自動では判定しない）。

## 通信先

`www.soumu.go.jp`・`*.lg.jp`（県選管）・`warp.da.ndl.go.jp` はクラウド環境の Allowed domains に入っていないと 403 になる（R16、ねくさんの設定待ち）。届かない日は自動更新が「届かない」と記録して飛ばす。
