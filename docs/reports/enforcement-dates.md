# 成立法（評価対象）の施行日 取得結果

評価対象 349 本の施行日を取った結果。3段階で取っている。

1. `scripts/fetch_enforcement_dates.py`: e-Gov 法令 API v2 の `law_revisions`（改正履歴）から取る。
2. `scripts/fetch_enforcement_fusoku.py`: 1で空欄だった法律について、現行法令の本文 XML（`law_file/xml`）の附則から、当該改正法の施行期日の条を読んで補う。
3. `scripts/fetch_enforcement_decrees.py`: 2でも空欄だった行（附則が政令で定める日とするもの、取得不可）について、施行期日を定めた政令の附則と改正履歴から補う。

結果は `data/acquired/enforcement-dates/enforcement.csv`（列「施行期日の原文」に附則の施行期日の条をそのまま残す）、
取得記録は同 `manifest.csv`（sha256 付き）。原本は `.local/enforcement-dates/raw/`（JSON）と `.local/enforcement-fusoku/raw/`・`.local/enforcement-decrees/raw/`（XML・JSON）に置き、git 管理外。

## 施行期日政令による補完（3段階目）

`scripts/fetch_enforcement_decrees.py` で、施行日が空欄のまま残った行に、施行期日を定めた政令を当たった。

| | 段階2の終わり | 段階3の後 |
|---|---|---|
| 施行日あり | 140 本 | 170 本 |
| 施行日が空欄 | 209 本 | 179 本 |
| うち 附則が「政令で定める日」とする行 | 175 本 | 147 本 |
| うち 取得不可 | 32 本 | 31 本 |

- 政令の附則から補えた: 30 本（取得方法「施行期日政令」）
- 改正履歴（law_revisions）から推定できた: 21 本（取得方法「改正履歴（law_revisions）の amendment_law_num 一致」）。**施行日には採らず、「施行日の候補」に移した**（下記）
- 空欄のまま: 179 本（全 349 本中。推定のみの 21 本を含む）

### 推定の 21 本を施行日に採らない判断

改正履歴からの 21 本は、改正履歴の版の日のうち、ただし書・各号に明示された日を除いて附則の期間内に一つだけ残る日を当てたもの。政令や法の原文で日そのものを確かめたものではない。
このプロジェクトは事実だけを使い推測を使わない規則なので、原文で確認できた日（政令の附則に法令番号と日が明示されたもの）だけを施行日に使う。
既定は Claude の判断で「確認済みのみ使う」とした。21 本は施行日を空欄に戻し、その日を「施行日の候補」に移し、備考の頭に「推定（改正履歴の期間内で一つだけ残る日。原文で未確認）」と付けた。
段階3より前に施行日があった行は変えていない。原文で確かめられれば、後から施行日に戻せる。

### 取り方

- 「〇〇法の施行期日を定める政令」そのものは e-Gov の法令データに無い（効力を終えた政令は引けない。`laws?law_title=施行期日を定める政令` は 0 件）。
- そこで法令 API v2 の全文検索 `keyword` で、閣令（`law_type=CabinetOrder`）から、当該法律の法令番号を含む文を探した。施行令・整備政令の XML には、効力を終えた改正政令の附則が `Extract` として残っている。
- 施行日に採るのは、法令番号が一致し日付が文中に書かれた次の形の文だけ（XML 本文で再確認し、原本を `.local/enforcement-decrees/raw/` に置いて sha256 を manifest.csv に追記）。
  - 「この政令は、〇〇法（法令番号）の施行の日（平成…年…月…日）から施行する。」
  - 制定文が「〇〇法（法令番号）の施行に伴い」とある整備政令で、附則が「〇〇法の施行の日（日付）から施行する」とあるもの。
- 「附則第一条第二号に掲げる規定の施行の日（日付）」は一部の規定の日なので、施行日に採らず候補に入れた。
- 政令どうしで日が食い違うもの、公布日より前の日、附則の「公布の日から起算して〇を超えない範囲内」を外れる日は採らない。
- 政令に記載が無いときは、改正履歴のうち amendment_law_num が一致する版の日から、ただし書・各号に書かれた日を除いて附則の期間内に一つだけ残る場合を推定した。原文での確認ではないので、施行日ではなく候補に入れた。
- 附則が「この法律は、〇〇法（法令番号）の施行の日から施行する」とするものは、〇〇法の施行の日を同じ方法で確認して採った。
- 取得不可の行は、現行題名・「案」を除いた題名・題名の先頭・法令番号で検索し直し、改正履歴に当該改正法の版を持つ法令を探した。
- 備考の「施行期日政令の照合」に、確定した根拠、または確定できない理由を書いた。「施行期日の原文」には、採った政令の附則の文を `【政令 …】` で追記した。

### 空欄のまま残った理由

- 施行期日政令は e-Gov に無く、施行令・整備政令の附則にも法令番号と日を明示した記載が見つからない: 122 本
- 改正対象または当該法律が廃止・改称されており、e-Gov の現行法令データから引けない: 30 本
- 政令の附則が書いているのは一部の規定の施行日だけで、主な施行日を示す記載が無い: 6 本

限界: e-Gov の保持する政令は現行のものに限られ、効力を終えた施行期日政令や古い施行令の附則は引けない。
官報などの別の原本は取っていない。確かめられない行は推測で埋めず空欄にした。

## 取れなかった理由

- 改正対象または当該法律が廃止・改称されており、e-Gov の現行法令データから引けない: 30 本
- 施行期日政令は e-Gov に無く、施行令・整備政令の附則にも法令番号と日を明示した記載が見つからない: 2 本

## 取り方と限界

- 改正法は、題名の改正対象（現行法令）の本文 XML で、`SupplProvision` の `AmendLawNum` が当該改正法の法令番号に一致する附則を探し、施行期日の条（第一条または見出し「施行期日」の条）を読む。
- 新規の法律は、その法律自身の最初の附則（`AmendLawNum` なし）を読む。
- 本文に和暦の日があればその日、「公布の日」なら公布日、「公布の日から起算して〇を経過した日」なら公布日に期間を足した日（取得方法に「計算」と書く）。
- 「政令で定める日」は空欄にし、備考に「政令で定める日（未確定）」と書く。実際の施行日は施行令などを別に引く必要がある。
- ただし書や各号に別の日があるときは、本文の日を主な施行日とし、他は「施行日の候補」に入れる。本文に単独の日がない（各号による区分施行）ときは空欄。
- 文言を解釈できないものは空欄のまま原文だけ残した。推測では埋めていない。
- 現行の本文は抽出附則（`Extract="true"`）を含み、廃止・全面改正された法令は引けない。そのため古い改正法ほど取れない。
- 前段で確定した施行日は変えていない。前段の候補と本文の日が食い違うもの（段階施行で、本文の日が改正履歴の候補に含まれないもの）は備考に書いた。
  - 該当: 1 本
- 題名から現行法令を引けない改称・統合された法令の一部は、現行法令の法令IDを `RENAMED` 表に手で入れて引いた。採るのは附則の `AmendLawNum` が当該改正法の番号に一致した場合だけなので、ID が違っても誤った日は入らない。
- 「本文 XML を取得できない（HTTP 404）」は、改正対象または当該法律が廃止済みで現行法令として引けないもの。
