# 評価エンジンの不変条件と性質テスト（2026-11-20）

札付け・類型・額・曝露ランキングの「数え方」について、反論の余地を減らすための反例探しと性質テストの記録。発見時は挙動を変えていない。C1 の加算順は符号点順に固定し、C2 の印は額の種類から出す関数に一本化した（C3 は未修正）。

関連：issue #240（残務の正本）、#236（リリース前再査読）、`docs/引き継ぎ.md`、ADR 0027・0028、`docs/計算式.md`（method-spec-v3.0、2026-11-19）。ゴール正本は `PROJECT_SSOT.md` と `docs/ロードマップ.md`（G1〜G9・R番号）。公開方針は ADR 0008。

### データの流れ（要約）

1. 成立法台帳 → 2系統振り分け → 結果（outcomes）に類型・分類・向き・個別額または理由。
2. outcomes で SKIP 以外 → macro が OECD 同産業中央値との差で参考額（結果＝額）。評価対象外・効果なし（定例）・額ありは入れない。
3. 台帳が outcomes・macro・抜き取り検証を1行に束ね、不合格の額は参考に下げる（`amount_demoted`）。評価対象外は額が無いので「不合格のまま」。
4. 曝露は macro の結果＝額かつ産業≠COVID を産業×年に展開し、役割比率で人・会派へ配る。関与の無い枠は未配分。人＋会派＋未配分＝期待値。
5. 公開用変換で、階層外・本数不足の内訳の額を伏せる（法律1本ぶんの額が読めないようにする）。

### 検証の手順（CI と同じ順）

`AGENTS.md` と `.github/workflows/verify.yml` に従う：

1. `cd app && npm ci`
2. 配布物生成（`python -m scripts.build_public_distribution ...`）

## 見つかった反例

発見時は直していない。各件に「なぜ壊れるか」1行と、その原因を突く試験を付ける。症状だけ抑える直し（skip・閾値緩和・例外握りつぶし・決め打ち）はしない。C1 は加算順の固定で、C2 は額の種類から印を出す関数で、それぞれ直した。

### C1. 階層が関与の入力順に依存する

- **なぜ壊れるか**：関与の加算順が入力順に依存し、浮動小数点の非結合性で中央値が 1e-14 ずれ、同点付近の先頭が入れ替わると階層の `leaderLow` が変わり後続の `tier` が変わる。
- **壊れる不変条件**：I5
- **ロードマップ／ADR 前提との食い違い**：ADR 0028・計算式は曝露の階層を同じ入力集合に対して一意の記述として扱う前提（G3 の「点あり／点なし＋理由」）。入力の並びだけで `tier` が変わると、同じ関与でも階層が再現しない。
- **最小再現**：`exposure-ranking-properties.test.ts`（種266由来の固定関与）。額の合計（I1）は保たれる。
- **原因を突く試験**：同ファイルの「leaderLow の差で後続の tier が入れ替わる」＋パイプライン全体（集計は `beforeAll`、試験本体は階層鍵の一致）。
- **直し**：加算の前に、群 ID・法律 ID・役割・院・配り先・重みの符号点順へ並べ、同じ関与集合の加算列を一つにした。階層比較の許容誤差は広げていない。`it.fails` は通常の試験にし、並び替えの性質テストを足した。

### C2. 参考額の行に確かさ「段階*」が残る

- **なぜ壊れるか**：`site_values` が `o["確かさ"] or (macro なら「参考」)` のため、outcomes に段階語があると参考額でも上書きされない。
- **壊れる不変条件**：I3（参考と確定の語彙が混ざらない）
- **ロードマップ／ADR 前提との食い違い**：ADR 0008 は確かさの印を「高・中・低・参考」と定める。到達点「参考額」なのに確かさが影響の段階語（段階1/2/3）のまま残ると、0008 の印の語彙と食い違う（G2 の「参考」表示の前提）。
- **原因を突く試験**：`tests/test_evaluation_invariants.py` の `CounterexampleC2DesiredPropertyTest.test_c2_desired_reference_amount_certainty_is_adr0008_vocabulary`。望ましい性質（参考額の確かさは ADR 0008 の語彙「参考」）を通常の試験にする。不具合があることを要求する試験は置かない。保存済みの台帳は再生成しない。
- **直し**：印の語は `certainty_mark` だけが決める。参考額は段階を見ずに「参考」。`expectedFailure` は外した。

### C3（境界）. L3 が中央値 0 と「悪影響＋便益で負」を食い違いに数えない

- **なぜ壊れるか**：`sign_conflict` の条件が4通り（正の便益×悪影響、負の便益×貢献、など）だけで、中央値0と悪影響＋負の便益を含まない。
- **ロードマップ／ADR 前提との食い違い**：ロジック検査 L3（向きと中央値の符号）の文言だけ読むと漏れに見える。G2 の「向きつきの額」検査の境界。仕様で「数えない」と書くか条件を広げるかは別 PR。
- **位置づけ**：境界試験で固定。

## 説明できない数字／説明できる数字

「なぜその値か」を、入力と式で辿れるか。

| 数字 | 説明できるか | 根拠 |
|---|---|---|
| 発議 0.4・賛成 0.2・反対 0.2・閣議 0.2 | **取り決め**（理論の一意性は無い） | 引き継ぎ 2章、ADR 0027。確立理論メモは Shapley–Shubik 案を出し、採用は判断待ち（#238） |
| 的中率の合格線 0.8 | 説明可（95% から意図的に変更） | 評価方法設計書 eval-design-v1.1、`scoring-constants.ts`。最終評価用標本で1回だけ測る |
| 関与法律の下限 5 | **取り決め**（感度の根拠は文書に無い） | ADR 0027 §2 |
| 上位3本占有率の上限 0.5 | **取り決め** | 同上。「1本で決まる人」を階層から外す |
| 院の半分 `HOUSE_SPLIT=0.5` | **取り決め** | ADR 0028 決定5 |
| `HIDDEN_DOMINANCE_REST_MIN=0.1` | **取り決め**（引き算で1人の額が読めるのを防ぐ） | ADR 0028 決定11、2026-11-19 |
| macro の窓 最大10年・コロナ前は2019年で切る | 説明可 | `build_macro_amounts.py` 先頭コメント（新型コロナを入れない） |
| 抜き取りの種 `SEED=20261030` / 標本2 `SEED_V2=20261119` | 説明可（再現のための固定種） | `build_evaluation_ledger.py`、`resample_verification.py` |
| 符号つき比率合計 0.6（=0.4+0.2−0.2+0.2） | 説明可（上の取り決めから機械的） | 曝露の期待値の係数 |

**説明できない（または取り決めとしか言えない）数字の列挙**：役割比率 0.4/0.2/0.2/0.2、下限5本、占有率0.5、院半分0.5、伏せ判定の残差比0.1。いずれも「なぜその値か」の実証的根拠はリポジトリ内に無く、変えるときは版上げと感度表が条件（計算式・ADR）。
