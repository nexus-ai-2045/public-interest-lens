## 4. 直しの提案（原因ごとの小さい PR。まだ作っていない）

- **PR-A（public-interest-lens、このスレッドで可）**：`app/e2e/public/ranking.spec.ts` の「490本」を、配布データ（`ranking.json` の共有額のうち経済全体の本数）から読む形に変える。数字を写して持たない。あわせて、公開 E2E を pull request ごとに回す場所を決める。おすすめは、既存の verify ジョブに手順を1つ足す（実測 56秒、新しいジョブは作らない）。CI を増やさない決め（10-11）とぶつかるので、司令塔の判断が要る。
- **PR-B（repo-preflight）**：端末名の完全名が短い英数字だけのとき（例：6文字未満）は、前後が英数字でない場所に限って当てる。検査を緩める変更なので、理由を書いてねくの確認を取る。
- **PR-C（public-interest-lens、このスレッドで可）**：`scripts/preflight.py` の「権限」で、フックが止めたときと権限が無いときを分けて表示する。浅い clone のときは先に全履歴を取るよう、進め方 2章の1に1行足す（docs は司令塔の統合 PR へ回す）。
- 注意点（直しではない）：`E2E_NO_BUILD=1` の公開 E2E は、直前の dist が公開版でないと 10本が偽の失敗になる。総点検の順番では起きない。単独で回すときは `E2E_NO_BUILD` を付けない。
