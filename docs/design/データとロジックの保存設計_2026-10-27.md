# データとロジックの保存設計

日付：2026-10-27。状態：Claude Codeの条件付き賛成と4指摘を設計へ反映し、PR21・PR22の実装を記録した。原本保管先の移行、権限拡張、新版サイトの配信は未実施。実データ全体の内容精査・再評価は未完了。

## 対象と完了条件

製品のコード、原本、整形データ、判断、計算結果、サイトへの配布を分離し、同じ入力と版で再生成・検証・訂正できるようにする。新しいリポジトリやDBを増やすこと自体を目的にしない。まず既存の登録器・R2/D1・配布生成器を再利用する。設計の受入条件は既存実装との整合とClaude Codeの具体的レビュー回収。実装の受入条件は下記の再現性・公開境界検査の成功であり、実データ内容の正しさとは分ける。

## 保存するものと正本

| 層 | 内容 | 編集元・保存先 | GitHub・公開との関係 |
|---|---|---|---|
| ロジック | 取得器、整形・照合・計算、スキーマ、テスト、方法仕様 | 製品repoの scripts/、app/src/、data/*-schema.sql、既存ADR・計算式 | コードと方法の正本。ブランド名義でPRレビュー |
| 原本 | 公式PDF・HTML・元CSVと取得記録 | 既存 register_external_material.py でタスク別登録。ローカル .local/external-materials/ は作業・復旧用、遠隔保管は既存の非公開R2 public-interest-lens-raw | 原本のbyteと取得来歴を保持。全文をpublic Gitへ一括追加しない |
| 原本索引 | 原本hash、保存キー、URL、観測日時、byte数 | 既存D1 public-interest-lens-index は検索用投影。原本・取得記録から復元可能にする | 公開用索引は許可列のみ。D1への登録成功は内容検証ではない |
| 整形した観測 | 年・単位・政策ID・人物ID等をそろえた表 | data/acquired/ の既存表。小さい公開許可済み入力はGit、大容量・個人支払先等は非公開保管、所在はmanifestで参照 | 原本の代替にはしない。欠損・除外・対象時点を保持 |
| 判断と計算入力 | 因果の根拠、反証、人物同定、2系統の判断、採否、方法のパラメータ | 既存の評価・受領書・台帳の形式へ接続。個人情報を含むAI原文は非公開、レビュー済み投影のみ公開候補 | AI推定を観測値へ上書きしない。評価方法の意味変更は既存の人間レビュー境界を維持 |
| 計算結果 | 法律別・人物別の額、幅、未評価と保留理由 | data/derived/ と data/distribution/generated/ の世代別成果物 | 手編集を正本にしない。大容量の公開可能な成果は既存方針の同repo Release添付を候補にする |
| サイト用配布 | 許可した列だけのランキング・根拠・状態JSON | app/public/distribution/。生成器からのみ作る配信コピー | 原本保管庫・内部DBをブラウザへ直接渡さない。配信版を固定して公開 |

## 論理的に分け、すぐ物理移転しない

コードrepoとデータrepoの二重管理は現時点では採用しない。最初は同一repo内の役割と入出力を明確にする。公開済みの小さな入力や派生表は互換性のため残し、原本から再生成できることを確認してから配置を変更する。R2は原本等の非公開ファイル保管、D1は検索索引、SQLiteは再生成できるカタログとして使い分ける。

## 再現性と版の結び付け

入力を固定 → 整形 → 根拠と帰属を照合 → 計算 → 公開用投影 → 版を固定して配信、の順とする。原本取得、内容検証、計算成功、公開可否を独立した状態として保持する。未取得・未評価を0へ変換しない。

既存の世代ID・current.json・受領書の仕様を拡張する。新たな並行manifest規格を作らず、各生成器に不足する情報を既存形式と互換性を保って加える。必要な結び付けは、入力ファイルごとのSHA256と版、方法仕様の版、生成器が実際に使うソース群のSHA256、計算条件、出力SHA256、件数・対象期間・欠落・採否理由、検証結果への参照。Git全体のコミットhashは配布内容へ埋め込まない。無関係なコミットでも出力が変わる循環を避け、ソース群のhashと方法仕様版で束縛する。取得時刻・実行コミット等の監査情報は非公開の実行記録へ分ける。時刻などの来歴情報と計算内容のhashは分離し、同じ内容の再実行で別の計算結果と誤認しない。

点数なし事例は build_public_distribution.py の内容由来の世代とcurrent.jsonを持つ。人物・法律配布は独立の契約を持ち、人物配布の入力には ranking.json のhashも含めた。生成ソースと方法版は各配布のgeneratedFromへ束縛した。入力と来歴を追えるようにしたが、点数なし事例の scoringStatus=held を人物ランキングへ流用しない。

計算コードはネットワークや最新データを暗黙取得せず、指定した入力で計算する。取得と計算を別コマンドにし、欠落・改変・不明な版では停止または明示的な保留にする。サイト用投影を生成しても、公開への切替とは別工程とする。

## 検証の循環

- 入力：原本byte数・hash、取得時刻、単位・母数・欠測を照合。
- 処理：二重計上、誤同定、2系統不一致の保留、会計・配分の不変条件を回帰検査。
- 再現：同一入力・条件・コードで出力内容hash一致。入力改変・欠落・版不一致で検知。
- 配信：許可列だけを投影し、個人支払先・秘密・端末パスを除外。表示版と生成版を照合。
- 訂正：誤りを入力・判断・式・配信の原因へ戻し、修正前後の差と影響する結果を再生成。旧版を消して差を隠さない。

## 2026-10-27 来歴の束縛と残る確認

法律・主要議員・全議員参考一覧の配布契約を更新し、生成器と方法仕様の来歴を必須化した。NodeはViteの実依存グラフ、Pythonは既存の共通path_guardと明示した生成ソースを使い、独自のパス検査器・TypeScript解析器・別DBを作らない。生成器・共通helper・方法仕様とNode lockを照合する。schemaの更新は配布形式の更新で、方法仕様v2.2と金額の計算は変えない。旧形式や来歴欠落を画面で受け付けず、同一ビルドでJSONとクライアントを揃える。

法律の生成では、全入力byteを一度だけ捕捉して計算とhashに使う。額の目安に使うindustry_vaとコロナ分類も入力へ含め、出典による実効保留集合をparametersへ記録する。出典検査記録が無い場合は空の成功と扱わず停止する。Nodeの既存一次/参考生成器は入力テキスト・投票ファイルを捕捉済みで、そこへ実ソース来歴を付ける。

旧Gitの3大容量CSVは既知hash/byte数と照合してGit管理外の作業入力として復元した。現在の公式資料を改めて内容検証したという意味ではない。通常CIは公開入力とソースを検査し、private入力を持つ段で既存データ検査を省略せず回す。skip許可や上限は変更しない。

公開配信はVercel側の旧repoId参照が実測で見つかった。配信buildの生成と生成後検査はPR22で実装済み。既存team/projectのrootと外部ソース利用設定を維持したGit接続の修復と配信後の照合は、別の工程として行う。新規project、権限拡張、認証再作成はこの設計だけで許可されたものではない。
