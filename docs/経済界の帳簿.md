# 経済界の帳簿（business-ledger-v1）

経済界（経団連・商工会議所・業界団体など）の公表された要望から、該当する法律の改正と、その法律の結果までを並べる帳簿。**点数・順位には入れない**（ADR 0014 決定9〜11 と同じ別帳簿）。議員の因果の鎖（行動→結果→損失）の「背後の力」の欄として、法律IDで結ぶ。

## 境界と責務

- 本務：要望→（所管省庁の回答）→該当法令→要望から3年以内に公布された当該法令の改正法→その法律の結果、の対応を一次資料つきで残す。
- やらないこと：要望が改正の原因だと言うこと／団体や個人への点数づけ／新規の取得（既存の照合済みデータだけを使う）／法律の額の計算（`all-laws-v1` が正本）。

## 正本（SSOT）

| 材料 | 正本 | この帳簿での扱い |
|---|---|---|
| ロビー活動の経路①：規制改革ホットラインの要望（提案主体・提案事項・回答・該当法令・出典） | `data/acquired/blocking-actors/1_regulatory-requests/hotline*.csv` の原本照合済みの行 | 354件を読むだけ。書き換えない |
| 経路②：審議会・検討会での業界団体の発言 | `data/acquired/blocking-actors/2_shingikai/*.csv` の原本照合済み・区分「業界団体」 | 28件を同じ列に直す |
| 成立法・公布日 | `data/acquired/bill-census-full/enacted.csv`（題名に「改正」を含む法律） | 読むだけ |
| 法律の結果・額・確かさ | `data/derived/all-laws-v1/outcomes.csv` | 列を引くだけ。額は再計算しない |
| 団体名のそろえ | `scripts/org_names.py` の `org_key()` | 政治資金・団体の帳簿と同じ関数 |

## 出力（`data/derived/business-ledger-v1/`、`python3 scripts/build_business_ledger.py`）

- `requests.csv`：経路ごとの行（要望354＋審議会28）。「経路」列で分ける。受付日（受付番号 YYMMDDnnn の平成年月日を優先、無ければ受付日）、提案主体と区分、所管省庁の回答、該当法令から取り出した法律名、3年以内の改正法の本数。
- `chain.csv`：要望×改正法の対応。公布までの日数、改正法の結果・額の表示・公開可否・結果の確かさ、両方の出典URL。
- `by-proposer.csv`：提案主体ごとの件数。個人・民間企業・民間団体は名前を出さず区分でまとめる。
- `summary.json`：件数。`rebuild_public.py` の団体の帳簿の次で作り直す。

## 約束（読み間違いを防ぐ）

1. 「要望のあとに同じ法令の改正法が成立した」は**時間順の対応**で、要望が原因だという証拠ではない。全行の「対応の確かさ」に「低」と明記する。条文と要望の中身の照合は次の段階。
2. 結ぶのは受付から3年以内（`WINDOW_DAYS`）に公布された改正法だけ。窓は規制改革実施計画の期限に合わせた置き値で、動かすと対応の数が変わる。
3. 法律名を取れない要望（政省令・通知・「記載なし」）は結ばない。382件中171件で法律名が取れ、59件が改正法に結ばれた（2026-10-29 時点）。
4. 回答が「対応不可」でも、同じ法令が別の動機で改正されることはある。逆に回答が「対応可能」でも改正は起きうる。
5. 要望した側は経済界の一部の声で、反対側（規制を守りたい側）は `org-ledger-v1/org-stances.csv` に別に残している。両方を並べずに片方だけで評価しない。

## 次の段階（採用済み・未実装）

- 条文照合：改正法の附則・改正条文が要望の求めた内容に当たるかを2系統の AI で読む（当たったものだけ「確かさ：中」に上げる）。
- ロビー活動の残りの経路（取り込みは別PR。引用・法律名の機械照合に加えて独立AI2系統の一致を条件にし、取得資料は `scripts/register_external_material.py` で `.local/external-materials/` に保存してから照合する）（ねく 2026-10-29「陳情・与党部会ヒアリング・政策提言・メディアも」）：経団連などの政策提言・要望書、与党部会・党への陳情、メディアの論調・キャンペーン。取り込みは DOM の直接読み取り・Claude in Chrome・エージェントブラウザのどれでもよい（効率優先）。取得ごとに HOSTS・PIPELINE へ追加し、経路列に足す。メディアは報道・評論の扱い（これまで不採用）が方針変更になるので、「事実の報道」と「論説・キャンペーン」を区分して別欄にする。
- 議員の因果の鎖への接続：法律IDで `allocation-v1` の関与と結ぶ（点数外の「背後の力」欄）。
