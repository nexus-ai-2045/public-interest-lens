# 提案：便益ルール benefit-rule-v1（規制の便益を測り、損失額と差し引いて公開の可否を決める）

日付：2026-10-17。状態：提案（未承認）。設計決定0007 §5 の「事前に固定するルール」に当たるので、採用には人の承認が要ります。この段階ではコードを変えていません（下の「6. コードとの関係」）。

## 1. 問題

- `loss-rule-v1`（`app/src/loss-rule.ts`）は、規制の便益（`regulationBenefitYen`）が未測定（`null`）なら、額を計算しても `publishable=false` にします。規制は安全・消費者保護・金融の安定などのために経済活動を抑えることがあり、付加価値の減少だけを「損失」と書くと、狙った便益を無視した一方的な数字になるためです。
- `loss-v1` では15本すべてで便益が未測定です（`loss.csv` の「規制の便益：未測定」）。額が出た6本（通信2・宿泊3・貸出の参考1）も公開できません。
- 便益を「どの法律で、何を、どの公的統計で、どう測るか」を、法律ごとの人の判断なしに決める規則がありません。この提案はその規則です。

## 2. 額が出た法律と、法律が掲げる便益の候補

### 2-0. 前提

- **法律の目的の原文（第1条の目的規定）はリポジトリにありません。** `data/acquired/enforcement-dates/enforcement.csv` にあるのは施行期日の条文だけで、`bill-census-full/enacted.csv` も題名・提出者・審議経過だけです。下の「掲げる便益」は**題名から読める範囲**の候補で、確定には e-Gov 法令 API v2 の第1条（改正法なら、改正される法律の第1条と、法案の「理由」）を取ります（下の 5 の D1・D2）。
- 「取得済み」は `data/acquired/` にあるもの、「未取得」は出典の URL 候補を付けたものです。
- 便益の統計にも、損失額と同じく**比較群**（比較国か、影響を受けない国内の集団）が要ります。比較群が作れない統計は、取得しても「未測定」のままです（`impact-v1` の「比較群なし」と同じ考え方）。

## 3. 規則の案

### 3-1. 流れ

1. **目的の分類（AI 2系統）**：第1条（と法案の「理由」）の原文から、上の 2-4 の便益の種類を付ける。複数可。各系統は引用した条文の文字列を記録する。2系統が一致しなければ「未測定」。
2. **内包の判定（AI 2系統）**：その種類が「経済（付加価値に内包）」だけか。一致しなければ「未測定」。
3. **向きの矛盾の判定（AI 2系統）**：目的が損失額の指標を抑えること（例：金利の上限を下げて貸出を抑える）か。一致して「抑える」なら、その指標の減少は損失に数えず保留（R2）。
4. **便益の指標の測定（プログラム）**：種類ごとに 2-4 の指標を `impact-rule-v1` にかける（比較群・開始日・窓は損失額と同じ）。
5. **円への換算（プログラム）**：公的な単価がある種類だけ。差の件数 × 単価を、損失額と同じ年数だけ足す。
6. **公開の判定（プログラム）**：下の 3-3 の表。

AI が行うのは 1〜3 の当てはめだけで、数値はすべてプログラムで出します（設計決定0007 §4）。

### 3-2. 便益の状態

| 状態 | 意味 | `regulationBenefitYen` に渡す値 |
|---|---|---|
| 内包 | 目的が経済だけで、損失額の系列に入っている | 0 |
| 円換算済み | 指標で段階1以上・貢献が出て、公的な単価で円にできた | その額（中央値。幅は 3-5） |
| 検出されず | 指標の測定はできた（開始前3年以上・開始後2年以上・比較群あり）が、差がばらつきの2倍を超えて2年続かない | 0（判断事項1） |
| 検出・未換算 | 段階1以上・貢献が出たが、公的な単価が無い | null |
| 未測定 | 原文が無い、2系統が不一致、系列なし、比較群なし、期間が足りない | null |

指標が悪化した（段階1以上・悪影響）場合は、円換算できれば負の便益として渡し（損失が増える）、できなければ null にします。

| 行 | 条件 | 結果 |

### 3-4. 新型コロナの窓

- 原則：損失額の窓が2020〜2022年と重なる行は公開不可（R3）。判定ルールは同時期の別の出来事を除かず、宿泊・飲食の名目付加価値は2019年14.5兆円から2021年7.5兆円に落ちたので、額の大半がこの時期の差だからです。
- 分離できる場合（推奨の既定）：開始後の窓を2019年で切っても、開始後が2年以上あり、`impact-rule-v1` の段階と向き、`loss-rule-v1` の額の向きが同じになるときだけ、**2019年で切った額**を公開の候補にします。年を飛ばして2023年以降をつなぐことはしません（系列接続禁止と同じ考え方）。
- 今の6本に当てはめると：衆法-186-35（2014〜2019年の6年）・閣法-189-27（2015〜2019年の5年）・衆法-189-20（2017〜2019年の3年）・閣法-196-4（2018〜2019年の2年）は切った額を計算できます。閣法-196-2（2019年の1年だけ）と閣法-201-24（2020年開始）は分離できず公開不可です。切った額が元の判定を再現するかは未計算です。
- 便益の指標の窓にも同じ規則を当てます。

### 3-5. 幅と二重計上

- **幅**：損失額の幅（第1〜第3四分位）と便益の幅を、向きが厳しい側で組みます。純損失の下限＝損失の下限−便益の上限、上限＝損失の上限−便益の下限。
- **内包したものは足さない**：目的が付加価値に入る経済の効果（観光振興・資金の供給など）は、別の便益として足しません。
- **移転は数えない**：税収、補助金、利払いの増減（貸し手と借り手の間の移し替え）は便益にも損失にも数えません。国際観光旅客税の税収はこれに当たります。
- **売上は足さない**：旅行消費額などの売上は付加価値ではないので、付加価値の損失額と足しません。
- **同じ便益の統計を何度も数えない**：損失額の観測グループと同じく、同じ便益の統計で窓が重なる法律は「便益グループ」にまとめ、グループの中の便益を足しません。1つの法律の中で、2つの種類が同じ統計を指すときは1回だけ数えます（例：消費者保護と金融の安定がどちらも破産件数を指す）。
- **同じ単価の二重使用をしない**：件数×単価で円にした種類と、同じ被害を含む被害額の推計（消費者庁の推計）を両方足しません。どちらか一方（既定は件数×単価）。

## 4. 人が決めること（3つ）

| # | 決めること | 推奨の既定 | 既定にした場合 | 別の選択をした場合 |
|---|---|---|---|---|
| 1 | 「検出されず」（測れたが差が出ない）を便益0とみなしてよいか | 0とみなす。表示に「便益は検出されず」と書く | 内包・検出されずの行は、新型コロナの規則を通れば公開の候補になる | 0とみなさないと、非経済の目的を持つ法律はほぼ公開できない |
| 2 | 新型コロナの窓の扱い | 2019年で切った窓で判定と向きが再現する場合だけ、切った額を候補にする（3-4） | 6本のうち4本が切った額の計算対象になる。年数が短くなり額は小さくなる | 一律に公開不可なら6本とも公開不可。注記付きで公開なら、額の大半が新型コロナの差のまま出る |
| 3 | 円への換算に使う単価 | 公的機関が公表した単価だけ（PIO-NET の平均既支払額、内閣府の交通事故の原単位など）。無い種類は円にしない | 金融の安定・犯罪・プライバシー・環境は「検出・未換算」になり、検出されれば公開不可 | 研究論文などの単価を認めると公開できる行は増えるが、実測だけという設計決定0007 §1 から外れる |

## 6. コードとの関係

- `loss-rule-v1` には既に便益の差し込み口（`LossInput.regulationBenefitYen`）があり、`app/src/loss-batch.ts` は今すべて `null` を渡しています。3-2 の表の値をここに渡せば、内包・検出されず・円換算済みの行は `publishable=true` になります。そのため、この段階では `loss-rule.ts` を変えていません。
- 足りないのは、新型コロナの規則（R3）、向きの矛盾（R2）、便益の幅（3-5）です。`loss-rule-v1` は便益を1つの値として三つの四分位から同じだけ引くので、幅は扱えません。採用されたら、`loss-rule.ts` は変えずに、別の `app/src/benefit-rule.ts`（`benefit-rule-v1`）に便益の状態と公開の判定（3-3）を置き、`loss-batch.ts` から両方を呼ぶ形を提案します。テストは 3-3 の各行を人工データで1つずつ確かめます。

## 7. 限界

- 題名から読んだ便益は候補にすぎません。D1・D2 の原文で分類し直します。
- 非経済の便益の多くは、比較群が作れず「未測定」になります。そのとき公開できないのは、規則が厳しく働いている印で、失敗ではありません。
- PIO-NET の相談件数は被害の一部しか捉えず、件数×平均既支払額は被害の下限です。
- 2019年で切った窓は年数が短く、額は小さく、開始後の効果の立ち上がりを含みやすくなります。
