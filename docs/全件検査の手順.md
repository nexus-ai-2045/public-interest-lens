# 全件検査の手順（額を計算済みで共有額により画面外の法律）

方式は nexus-ai-skills の `bulk-logic-audit-fanout` に従う。道具は `scripts/audit_fanout.py`。ねくの方針は精度最優先とトークン効率の両立：**機械で決まるものは全部スクリプト、モデルには機械で決まらなかった件だけ渡す**。

## 対象
台帳（`data/derived/evaluation-ledger-v1/ledger.csv`）で、全体指標の参考の額が付いていて、同じ額が2本以上ある法律（共有額で画面外）。参考に下げ済みは除く。2026-10-31 時点で1,858本。問いは2つだけ。
- 範囲：この法律の対象は産業全体か一部か（全体／一部／不明）
- 分類：評価対象か制度整備か（評価対象／制度整備／不明）

## 線引き
| 機械（トークンを使わない） | モデル |
|---|---|
| 対象の選別、旗付け（狭い題名に経済全体・付加価値1年分に対する割合・共有額・制度語）、束分け、返却の形式検査、欠け・重複・未回収の検出、判定の突合、表・根拠記録・較正率の集計、抜き取りの選定 | 旗で決まらなかった件の範囲・分類の判定、A/B が割れた件の裁定 |

狭い題名に経済全体の額を当てた件（規則 L2）は、範囲が「一部」で不合格と機械で決まる。モデルに回さない（plan が本数を出す）。

## 4段
1. **段1 旗（スクリプト）**：`python3 scripts/audit_fanout.py flag`。全件に旗を付け、機械で決まる件を除く。
2. **段2 Haiku A/B**：同じ束を独立に2本（A・B。互いの結果は見せない。B は並びを変える）。既定は1束40本、`--size` で変える。束を大きくしても、根拠引用・独立2本・引用検査は削らない。
3. **段3 裁定**：A/B が割れた（または不明を含む）件だけ Sonnet。Sonnet が A か B のどちらかと一致すれば採用。どちらとも違う・不明なら Opus。Opus は Sonnet でも決まらなかった件だけ。
4. **段4 較正（先に回す）**：正解既知の sample-verdicts.csv の118本を、先に同じ手順に通す。

## 手順（調整役）
1. 較正：議案本文を `python3 -m scripts.audit_corpus fetch ...` で取り、`plan --calibrate --corpus <本文の置き場> --out .local/audit-cal` → Haiku を束×A/B で並行起動（各子に `haiku/prompt/<束>.txt` を渡す。子は入力 JSONL を読み、`returns/haiku/<束>.jsonl` に書く）→ 全部回収 → `collect` で形式違反・欠けを確認 → `disputed --stage sonnet`、必要なら `--stage opus` を同様に → `calibrate --out ... --publish`。
2. **較正が低ければ全件に回さず報告する。** 基準は `data/derived/evaluation-ledger-v1/audit-fanout-baseline.json`（暫定：一致率90%以上、見逃し率5%以下、誤検出率15%以下、件数100以上）。`collect` と `calibrate` は基準以下・未実施・較正後にプロンプトが替わったときに警告を出す（`collect --strict` は終了コード2）。基準を検査に合わせて上げ下げしない。
3. 全件：`plan --out .local/audit-full`。Haiku は上限を置かず並行起動（子は短い1仕事）。返らない束は再実行の前に、上限と入力の欠けを見る。
4. `collect` で未回収の束・欠け・形式違反・重複を出し、未回収だけ回し直す。割れた件は `disputed --stage sonnet`、その結果で `disputed --stage opus`。
5. `sample --n 3` で種類×判定ごとに抜き取り、実物（原本）で確かめ、食い違い数を表に書く。子の判定は確かめずに表へ写さない。
6. `collect --publish` で表と方法の説明の元データを出す。不合格は降格規則（`evaluation_rules.is_demoted`）で参考に下げ、根拠つきで出し続ける。直したら同じ方式で全件をやり直し、基準を下げる。

## 子の返却（JSONL。形式違反は collect が弾き、未回収扱いにする）
問いは二値の小問に分ける。範囲1（対象は特定の業・対象者・期間・手続に限られるか）、範囲2（効果は額の産業全体に及ぶか）、分類1（付加価値を直接動かす変更を含むか）、分類2（条文の中心は組織・手続・期限・名称の整理に限られるか）を はい／いいえ／不明 で答える。範囲・分類は小問から決まり、script が突き合わせる（食い違いは形式違反）。

必須：`id`、範囲、分類、小問、根拠引用（資料欄の文言をそのまま。6文字以上。出典名つき）、使った前提、仮定（内容・強さ 強中弱・外したときの影響）、読んだ出典、計算や比較、判定理由（1〜2文）、確認できなかった点、探した場所、確信度、`model`、`prompt_version`（入力の版をそのまま写す）。無いときは「なし」か空リスト。不明なのに確認できなかった点が「なし」は違反。Haiku・Sonnet・Opus のどの段も同じ。

**引用検査**：根拠引用が入力の「資料」欄（overviews.csv・macro.csv の該当行。`plan --corpus DIR` で `<法律ID>.txt` の原文を足せる）に実在するかを、collect が空白を除いて突合する。実在しない引用は作り話として形式違反にし、その判定は採用しない。**A/B の一致だけでは採用しない**（共通の偏りは多数決で消えない）。引用検査を通った返却だけが判定になる。

## 凍結標本と検証（精度の主張に使う）
- 調整用：額ありの正解既知 `data/derived/audit-fanout-v1/calibration-truth.csv`（元の118本のうち額あり＋追加40本。作り方は `scripts/audit_corpus.py truth`）。元の118本の「合格」には額なしの法律（額なしが正しい、の意味）が31本あり、範囲の問いが成り立たないので母集団から外した。額ありの正解は、モデルの判定を見せず議案本文で決めた Opus で取り直した（元の正解10本中9本が覆った）。規則・プロンプトの設計と較正にだけ使う。
- 正解の合格が10本未満だと誤検出率は測れない（警告が出る）。額ありの母集団は合格がほとんど無いため。誤検出の害は参考への降格にとどまり参考値と根拠は残るので、**見逃し（誤って合格）を止める側を強くする**：合格と判定した法律は全件を、判定を見せない Opus が議案本文で再確認する。
- 検証用：`python3 scripts/audit_fanout.py sample --frozen --n 300 --seed 20261031` で、調整用を除いた対象から単純無作為に300本を凍結（`data/derived/audit-fanout-v1/frozen-sample.csv`。各件の抽出確率 π=n/N を記録）。凍結後は規則・プロンプトの調整に使わない。作り直しは `--refreeze`（調整に使ったなら、その標本は検証に使えない）。
- LLM とプロンプト版を固定してから正解（実物確認）を取る。固定前に正解を見ない。`plan --frozen` で束にし、`collect` が不合格数と95%上限（Clopper-Pearson。0本なら約3/n）を出す。
- 全件の判定と、標本の正解（`truth.csv`：id,判定,prompt_version）から、`ppi --out <全件の作業場> --truth truth.csv` が単純な PPI で不合格率を区間つきで出す。正解の prompt_version が全件の実行と違えば止まる。

## 仮定の台帳と根拠カード
`collect` が `assumptions.jsonl`（仮定ID→内容・強さの内訳・使った法律）を出す。仮定ID は内容の正規化文字列のハッシュ。各法律の `basis.jsonl` の行は、仮定IDと強さ・影響を持つ（根拠カード）。仮定を変えたとき、影響する法律を台帳から洗い出せる。Bourlès の弾性値のような外部の効果量は、個別の法律に直接は使わない。

## 共有額グループ
`plan` は `share-groups.json`（同じ額を共有する群ごとの本数・業界×期間・法律ID）を出す。共有額の総枠配分は別 PR で扱う。ここは件数を見せるだけ。

## 出力
- `collect.json`：表（種類／検査数／機械判定／合格／不合格／参考に下げた／確認不能／未決）、未回収、欠け、形式違反、重複、警告。
- `basis.jsonl`：法律ごとの根拠記録（根拠カード）。判定・理由・使った前提・読んだ出典・A/B の判定と一致・段と裁定者のモデル・プロンプトのファイルと版（git SHA とファイルのハッシュ）・`refBasis`（画面に写す短文）。
- `methodology.json`：方法の説明の元データ（較正の当たり率、基準、段ごとの一致率、使ったモデル）。`--publish` で `data/derived/audit-fanout-v1/` にも書く。画面（/methodology・法律の詳細）への表示は別 PR。

## プロンプトの差し替え
`prompts/audit_fanout/judge.txt`（Haiku）と `arbitrate.txt`（Sonnet・Opus）だけを直す。ハッシュが変わると、既存の較正は無効になり警告が出る。較正をやり直す。
