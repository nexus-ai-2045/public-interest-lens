# 原因の軸の計算（R44、cause-axis-v3 の実装）

式と決まりは `docs/計算式.md`「伸び損ねた原因の軸の額」が正本です。ここは実装の使い方と、文書の数字との照合です。

## 使い方
```
python3 scripts/prepare_oecd_stan.py <OECD 原本 CSV のディレクトリ>   # 固定入力を取り直すとき（単独の PR）
python3 scripts/build_cause_axis.py                                  # data/derived/cause-axis-v1/ と app/src/cause-axis.json を作る
python3 -m unittest tests.test_build_cause_axis                      # 手で解ける入力での検算＋Git の出力が最新かの検査
```
画面は `/world` の「産業ごとに、日本は同じ産業の他国より伸びたか」（`app/src/CauseAxisPanel.tsx`）。

## 出力（data/derived/cause-axis-v1/）
| ファイル | 中身 |
|---|---|
| `industry_gap.csv` | 産業ごとの累計（兆円）・置換検定の順位・確かさ・韓国を除いた感度 |
| `yearly.csv` / `peers.csv` | 比較画面の折れ線（日本と比べる国の中央値）と、国ごとの2023年の比 |
| `growth_accounting.csv` | 失敗した側の差の要因分解（働く人の数・資本・全要素生産性） |
| `axes.csv` | 軸（E1・F1・G1・R1・C2・M1/M2）ごとの額と扱い |

## 文書（2026-10-24）の数字との照合
額は文書7章と一致します：IT・情報サービス 50.0、出版・映像・放送 −14.8、通信 64.7、電子機器 −97.3、研究開発サービス 3.3、情報通信全体 104.8、経済全体 378 兆円、C2 の純額 −32.6 兆円（`tests/test_build_cause_axis.py` の「出力が最新か」は、固定入力から作り直した値が Git の出力と一致することを見ます）。

## 文書と違うところ（実装で決めたこと）
1. **置換検定の順位は、既定の額と同じ中央値の差で数え直した。** 文書の順位（IT 4位／14、通信 2位／15、電子機器 1位／14 など）は合成対照の差で数えたもの。仕様の文面（「同じ差を計算し」）に合わせて、中央値の差の置換にした。順位の数字は動く（IT 5位／14、通信 1位／16、電子機器 3位／14、出版 7位／14）が、**軸に結ぶ産業の確かさの判定（3位以内か）は文書と同じ**（参考＝通信・電子機器・経済全体、誤差の範囲＝IT・出版・研究開発サービス）。情報通信全体（J）は文書では合成対照で3位（参考）だったが、中央値の置換では6位（誤差の範囲）。J は軸の額には使わず、内訳の上限の確認にだけ使う。
2. **合成対照は移していない。** 文書でも感度の列だけで、scipy が要る（リポジトリの Python は標準ライブラリのみ）。必要になれば別 PR。
3. **成長会計の就業者の単位をそろえた。** 作業フォルダの元のコードは、単位（PS・PS_FTE・H・JB）が混ざった表の後勝ちで読んでいた。国ごとに PS に固定した結果、内訳が最大で数ポイント動く（情報通信の全要素生産性 78%→79%、働く人の数 −10%→−11%、経済全体の資本 70%、結論は同じ）。
4. 人口1人当たりの感度（文書2-2）と韓国を除く経済全体の感度は出していない（M1/M2 は配らないため）。

## 限界
- 比べる産業は STAN の7コードだけ。他の産業（製造業全体・金融など）への広げ方は未着手（R63〜R66 の前提）。
- 日本の IT・通信・出版・研究開発サービスは OECD に実質の系列が無く、親の産業の物価で割った仮定の値。成長会計はこれらでは出せない。
- 額は「軸に結ぶ観測の差」の上限で、人や組織には配っていない。
