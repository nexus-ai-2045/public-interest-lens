# 設計決定0010：本番の作業の前に、必ず事前チェックで止まる原因を測る

日付：2026-10-17。状態：採用（ユーザーの指示 2026-10-17 を記録する。マージで正本とする）。

## 背景

毎朝の自動更新やマージの途中で、通信先の未許可・入口の起動失敗・Vercel の枠切れ・個人名義検査の未実行などが分かり、作業が途中で止まることがあった。2026-10-17 にユーザーが「ドライラン、ブロッカー、プリフライト、ヘルプ、スモークを必ず先に通して、事前に測って」と指示した。

## 決定

1. 事前チェックの入口を `scripts/preflight.py` の1本にする。中身は次のとおり。
   - ドライラン：毎朝の作り直し（`scripts/rebuild_public.py`）が呼ぶスクリプトがそろい、構文が通るか。
   - ヘルプ：主要な入口が `--help` で起動できるか。
   - 止まる原因の検出：通信先、GitHub の権限、Vercel の枠、repo-preflight の個人名義検査、ロードマップの検査。
   - スモーク（`--smoke`）：公開版をビルドし、localhost で主要6画面を開く。
2. 結果は「合格・注意・失敗」に分ける。失敗が1つでもあれば終了コード1で、本番の作業に進まない。届かない取得元と Vercel の枠切れは「注意」で、作業は進める（設計決定0009 の「外部の待ちは止まる理由にしない」）。
3. 必ず先に回す場面は次の2つ。
   - 毎朝の自動更新：`scripts/daily_update.py` が最初に事前チェックを回し、結果を報告に載せる。失敗があれば再計算と公開ランキングを作らない。
   - マージ前：`python3 scripts/preflight.py --smoke` を回し、失敗が0であることを確かめてからマージする。
4. 結果は `.local/preflight/<日付>.json` に残す（Git に入れない）。

## 影響

- 新しい入口を足したら `scripts/preflight.py` の `HELP_MODULES` に、取得元を足したら `scripts/daily_update.py` の `HOSTS` に足す。作り直しの段は `scripts/rebuild_public.py` から自動で拾う。
- `docs/ロードマップ.md` の「進め方」と `docs/自動更新.md` に載せる。
