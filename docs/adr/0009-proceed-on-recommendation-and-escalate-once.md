# 設計決定0009：おすすめで進め、止まるときは1通にまとめて聞く

日付：2026-10-17。状態：採用（ユーザーの指示 2026-10-17 を記録する。マージで正本とする）。

## 背景

作業スレッドが判断や外部の待ちで黙って止まり、ユーザーがプロジェクトのチャットを見ても何が必要か分からないことがあった。2026-10-17 にユーザーが「全て推奨でゴー」「止まるんだったら聞いてください」「スレッドのままで止まられても困る。仕組み化して」と指示した。

## 決定

1. 判断が分かれるところは、おすすめ（推奨）を選んで進める。どれを選んだかは状態の表示と PR に書く。決まりきった手順には承認を求めない。
2. どうしても止まるとき（取り消せない操作、設定画面でしかできない操作、ユーザーにしか答えられない判断）は、黙って止まらない。次の2つを同じターンで行う。
   - スレッドに1通の返信を出す。何が必要か、どこで何を押すか（1〜2手）、おすすめの選択肢を書く。
   - 調整役（プロジェクトのチャットを見ている Claude）にも知らせる。調整役がプロジェクトのチャットでユーザーに聞く。
3. 待っている間も、止まった項目に依存しない作業は進める。
4. 外部の待ち（CI、自動レビュー、Vercel の無料枠）は「止まる」に入らない。状態の表示を更新して進める。
5. ロードマップでは、ユーザーの操作待ちの項目を状態「ねくさん待ち」にし、根拠の欄に「どこで何を押すか」を書く（例：R16）。

## 影響

- `docs/ロードマップ.md` の「進め方」にこの決まりを載せる。
- 「ブロック」という語は使わず、「ねくさんの○○待ち（どの画面で何を押す）」と書く。
