# 設計決定0027：点数の付け方を「点数設計 v2.1」にする（0014 の配り方と 0026 の重みを置き換える）

日付：2026-11-19（設計の確定は 2026-11-08）。状態：**採用（設計・実装済み）**。コードの移行は `method-spec-v3.0`（#210・#211）で終わり、旧方式（`allocation-v1`・`causal-shapley-v1`・`observation-split-v1`・全議員の参考の額）は公開データから消えた。議員の側は曝露ランキング（設計決定0028）だけで、画面にはまだ出していない（`MEMBER_RANKING_HIDDEN`、実名公開の線引きは設計決定0008 の確認待ち）。
置き換えるもの：[設計決定0014](0014-allocation-by-action-and-direction.md) の決定1（閣法の閣議決定の分を点数に入れない）・決定2の割合・決定5の配り先・決定6、[設計決定0026](0026-shugiin-individual-responsibility.md) の4章（重みの置き方）。
触らないもの：実名公開の線引き（[設計決定0008](0008-publish-everything-with-certainty-marks.md)）。0014 の決定3・4・7〜11、0026 の3章（どの行動を点に使うかの採否）。

名前の注意：ここでいう「v2.1」は点数設計の版で、計算方法の仕様の版（`method-spec-vX.Y`、設計決定0013）とは別の番号。仕様の版は `method-spec-v2.4`（この決定の取り込み。計算は変えない）。

## 1. 背景（測定）

- 産業別の額が付いた法律 1,982 本のうち、「同じ産業の他の法律が前後5年以内に無い」＝単独で効果を識別できる法律は **2 本だけ**（macro-v1 の産業・施行日で数えた。main 5a13f3c 時点）。
- 日本1国の産業統計だけでは、法律ごとの因果効果を差の差で積めない。識別できる単位は「産業×期間の群」まで。
- 旧方式の誤りは実測で確認済み：首相3人のマイナス、符号の的中が19本中10本、8人の首相で全議員の損失合計の54.6%（[計算方法の敵対的レビュー](../計算方法の敵対的レビュー_2026-11-01.md)）。
- 原因は5つ：額なしの指定（noAmount）の無視（#181 で修正済み）、向きを産業の差の符号で決める、産業×期間で唯一の法律に群の差を丸ごと付ける、閣法を首相1人に重み1で付ける、確かな額0なのに参考の表が順位に見える。

## 2. 決定

| 層 | 決めたこと |
|---|---|
| 主張の3種 | 事実／推定（幅つき）／取り決め。混ぜない |
| 識別の単位 | **産業×期間の群**。群の差（OECD 同産業・同時期の中央値との差）は記述として出す。「政策で説明できる割合」は出さない |
| 法律単位の額 | **外部証拠のはしご（他国の実測→官庁の見込み→業界統計→弾力性×規模）が取れた法律だけ**。取れなければ「測定できない」。**群の差を法律へ配らない**（本数で割る配り方も含めて廃止） |
| 向き | 産業の差の符号で法律の向きを決めない。外部証拠が無い法律は向きなし |
| 阻止・遅れ | 中立な定義（反対・阻止・遅延）。見込みの偏りは、成立した法案の「見込みと実測のずれ」で補正する。判定者に会派を伏せる。事前登録とプラセボ |
| 帰属 | 党への帰属を基本にし、個人は**役割ごとの固定比率（取り決めと明記）**。党と個人を重複して合算しない。責任度は比較用の別欄に出すだけ。**Shapley 値による配分は撤回** |
| 閣法 | 首相1人に付けない。閣議決定の分は、在任条件を満たす閣僚に均等 |
| 順位 | 同時信頼集合の階層で出す。幅と条件を満たさない人は「測定不能」 |
| 原因の軸（cause-axis） | 群の記述と同じ扱い。軸ごとの額は記述として出し続け、法律へも人へも配らず、順位と点に使わない。軸へ配る本数割りは、法律単位の額を作らない限り残す（廃止したのは、群の差を法律へ配る経路）。設計 v2.1 の文書に明記が無いため、2026-11-19 に推奨で決めた。戻せる |
| 税・マクロ | 消費税は乗数の幅つき別欄、法人税・金融規制は測定できない、特例公債法は許可型 |
| 実名公開 | 事実（賛否・役職）は全員公開（設計決定0008 のまま。0008 はこの決定で書き換えない）。因果の点（推定の額）は条件を満たす人だけ。曝露ランキングは記述として出す |

### 固定する定数（つまみにしない。変えるときは仕様の版を上げる）

値の正本は `app/src/scoring-constants.ts`。下の表は写し。

| 定数 | 値 | 理由 |
|---|---|---|
| 的中率（向きの一致率）の合格線 | 80%（2026-10-29 の 95% から変更。ねく 2026-11-19「進めれるだけ進めて」を受け、推奨の値で確定。評価方法設計書は `eval-design-v1.1`。`scripts/backtest.py` は #196 で同じ値） | つまみにすると通りやすい値に合わせてしまう。最終評価用の標本で1回だけ測る |
| 寄与法律数の下限 | 5 | 法律3〜10本で決まる「くじ引き」を防ぐ。5未満は点を出さない |
| 上位3本の占有率の上限 | 50% | 1本の法律で決まる人を除く |
| 確かさの下限 | 中以上 | **「低」と「参考」は順位にも配分にも使わない**（0014 決定6 を置き換える） |

### 残すつまみ（2つ）

| つまみ | 初期値 | 扱い |
|---|---|---|
| 個人の固定比率 | 発議 0.4・賛成 0.2・反対 0.2（逆向き）・閣議決定 0.2 | 取り決め。値を変えたとき順位がどう動くかを必ず並べて見せる |
| 順位の信頼水準 | 90% | 統計の幅の取り方。95% にすると「判定不能」の階層が増える |

### 点が出ない人の扱い

- 設計 v2.1 の3章の問い「点を出せる人が少数になることを受け入れるか」に、ねくは「いいえ（ランキングは出す）」と答えた（2026-11-08）。
- そこで、因果の点とは別に「曝露ランキング」を出す方針にした：関与した産業群の伸び損ねた額を、上の固定比率で人に配る。**因果ではなく記述**と明記し、階層で表示する。
- 集計器は `app/src/exposure-ranking.ts`（#194、純関数）。公開データと画面にはまだつないでいない。つなぐときに版を付けて仕様（`method-spec.ts`）に節を足す。
- 守る線：群の額を法律単位の額として付けたり表示したりしない（集計器は群の額を本数で等分した枠を数え方として使うが、出力に法律ごとの額は無い）。因果の点と足さない。

## 4. 検証（3つを分ける）

1. 計算の再現：同じ入力から同じ出力（性質テスト）。
2. 観測値の予測校正：成立済みの法律の、事前の見込みと事後の実測のずれ。
3. 因果の識別：外部の自然実験や対照がある法律に限る。**向きの一致率を、3の代わりにしない**。

性質テスト（追加）：法律単位の額が無い法律は人の点に入らない／党と個人に二重に配らない／群の差を法律へ配る経路が存在しない（型で作れない）／固定した定数は設定から変えられない。

## 6. 比べた案

| 案 | 採否 | 理由 |
|---|---|---|
| A 旧方式のまま（群の差を法律へ配り、Shapley で人へ） | 不採用 | 誤りが実測で確認済み |

## 7. 影響

- 因果の点が出る人は少数になる。出ない人は、曝露ランキング（記述）と、関与した群・本数で見せる。
- 額・順位の変化：この決定の取り込み（`method-spec-v2.4`）では計算を変えないので 0。動くのはコードの移行の PR で、そのとき設計決定0013 の「変更の記録」に上位の動きを書く。
- 取り消せるか：文書の決定なので戻せる。定数を緩めるときは、理由を書いてねくの確認を取る。

## 8. 認知の罠

- 「全員に点が付く」ことを正しさと取り違える。
- 手法の洗練（差の差）が、データの少なさを隠す。先に本数を数える。
- つまみを増やして、決める責任を後回しにする。
- 曝露の額を因果の額として読む。画面と文書の両方で「記述」と書く。
