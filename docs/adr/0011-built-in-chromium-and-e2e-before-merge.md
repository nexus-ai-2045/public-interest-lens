# 設計決定0011：画面の確認はクラウド内蔵の Chromium で行い、マージ前に主要ページの E2E を通す

日付：2026-10-18。状態：採用（ユーザーの指示 2026-10-18 を記録する。マージで正本とする）。

## 背景

画面の確認や官公庁サイトの操作に、持ち主の Mac の Chrome（Claude in Chrome）を使うことがあった。持ち主の画面でタブが次々に開いて動くため手間がかかり、持ち主が席にいないと進まない。2026-10-18 にユーザーが「ブラウザは内部ブラウザに決める。Chrome が動くのが面倒」と指示した。あわせて、事前チェック・E2E・スモーク・ドライラン・ヘルプをしっかり回すよう指示した。

これまでのスモーク（`npm run preview:check`）は主要6画面が開くことだけを見ていて、一覧の絞り込み・行の詳細・議員ページのつまみなどの操作は機械で確かめていなかった。

## 決定

1. 画面の確認・スクリーンショット・ブラウザでの操作は、クラウドの環境に入っている Chromium（Playwright、`/opt/pw-browsers/chromium`）で行う。持ち主の Mac の Chrome は使わない。`playwright install` はしない。
2. 官公庁サイトのようにクラウドの通信先で届かない取得元は、Mac の Chrome で迂回せず、ロードマップの R16（クラウド環境のネットワークに `*.go.jp` を許可する）で解く。届かない間は「注意」として飛ばし、作業は止めない（設計決定0009・0010）。
3. 公開版の主要4ページ（`/ranking`・`/members`・`/world`・`/methodology`）の表示と操作を確かめる E2E を `app/e2e/public/` に置き、`npm run test:e2e:public`（`app/playwright.public.config.ts`）で回す。パソコン幅とスマホ幅の両方で回す。データの件数は毎朝変わるので、固定値ではなく「0より多い」「操作の前後で変わる」で確かめる。
4. 事前チェック `python3 scripts/preflight.py --smoke` に E2E を含める。マージ前は、スモークと E2E を含めて失敗が0であることを確かめる（設計決定0010 の3を広げる）。
5. 公開版の E2E は GitHub Actions（`verify`）には入れず、マージ前の事前チェックで手元で回す。Actions の実行枠が足りず、CI の段を増やさない方針のため（2026-10-11 ユーザー指示）。`verify` の `npm run test:e2e` は従来どおり開発版の E2E だけを回す。

## 影響

- 画面を足したら、`app/scripts/local-preview-check.mjs` の `PAGES` と、`app/e2e/public/` の E2E の両方に足す。
- 手順は `docs/ローカルで画面を確かめる.md` に載せる。
- Mac の Chrome が要る作業は、設定画面の操作など持ち主にしかできないものに限る。
