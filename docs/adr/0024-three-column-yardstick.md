# 設計決定0024：額の物差しを三欄にする（付加価値／国の収支／採算）

日付：2026-10-30。状態：採用（設計と税制改正12本の置き場まで実装。残りの法律への展開は検証スレッドの違反一覧に沿って行う）。ねく 2026-10-30「マクロ・ミクロの経済学とビジネスの損得を土台に、人情は省いて機械的に正しく計算する」。

## 決めたこと
1. **評価の土台：** 現代のマクロ経済学（GDP・付加価値）とミクロ経済学（誰が得して損したか）を基礎に、ビジネスの採算（投資対効果）の見方を添える。レイオフなどへの配慮は計算に入れない。ただし失業期間の付加価値の損失のような測れる量は残す。
2. **額は三欄に揃える。**
   | 欄 | 中身 | 順位・合計・配分 |
   |---|---|---|
   | 付加価値の増減（本線） | 産業の付加価値（GDP）の変化を円で | **これだけを使う** |
   | 国の収支（別表） | 税収の増減、給付・補助の支出など、国の財布の動き | 足さない・使わない |
   | 採算（参考） | 付加価値の増減 ÷ 国の支出 | 使わない。国の支出が分かる法律だけ |
3. **二重計上を作らない。** 税や補助金の移し替えは、それ自体は得でも損でもない。国の収支の欄を本線に足さない。
4. **確かさの印は必ず付ける。** 低いものは「参考」で折りたたむ。
5. **産業全体の差を1本の法律に丸ごと当てない**（R60）。範囲の合わない額は付けない。

## 実装の現状
- 国の収支の欄：`data/derived/tax-impact-v1/fiscal.csv`（毎年の税制改正12本、財務省の見込み、確かさ高）。`scripts/build_tax_impact.py`。台帳では経路「財政（税収見込み）」で、損失表・ランキング・議員の配分に入らない。
- 付加価値の欄：従来の損失・便益の額（段階1〜3、確かさつき）。
- 採算の欄：国の支出が一次資料で分かる法律が少ないため未実装。D（予算額）が固まった後に足す。
- 古い「単一の額」前提のコードの掃除は、検証スレッドの違反一覧（向きと符号の食い違い18本、狭い題名に全産業の額125本、出典なし13本）の修正と同じ PR で行う。

## 認知の罠
- 「額が出た」ことと「正しい」ことは別。三欄に分けても、本線の額の正しさは検証スレッドの抜き取りで確かめる。
- 国の収支が大きい法律を「経済効果が大きい」と読みやすい。別表にしたのはそのため。
