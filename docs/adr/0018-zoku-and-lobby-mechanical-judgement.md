# 設計決定0018：族議員・議員連盟・利権団体（ロビー活動）を一次資料から機械的に判定する

日付：2026-10-29。状態：オーナー（ねく）の依頼（ロードマップ R30）で、推奨を採用。実装は `scripts/build_zoku.py`、出力は `data/derived/zoku-v1/`。

## 境界と責務

- 責務：「誰が・どの分野に・どう関わり続けているか」「どの議連・団体が何を推進／反対し、その法案はどうなったか」を、公表された事実だけで並べる。
- 範囲外：不正・癒着の断定、属性（出自・国籍・信仰・家族）への印、記事・番組の論調への点（設計決定0014）、点数・順位への算入（本決定は別帳簿。R29「背後の力の帳簿」から議員の因果の鎖へ結ぶ）。

## 判定の基準（結果を見て閾値を動かさない。動かすときは先にこの記録を改める）

分野＝閣法の所管省庁（`ministry-v1/cabinet-bills.csv` の所管_今）。衆法・参法は所管が決まらないので分野に入れない。

1. **族議員の機械判定「分野との継続的な関わり」**（議員×分野）。次のどちらか。
   - A 委員長：その分野に対応する委員会（`COMMITTEE_FIELD` に固定。手続の委員会は分野なし）の委員長を2国会回次以上。
   - B 法案への行動：その分野の閣法に対し、提出・決定・修正・委員長・支持の質疑（2系統一致で算入済みのもの）が5本以上、かつ3つ以上の別の年。
   - 参院本会議の賛成票は誰でも持つので判定に使わず、賛成・反対の本数を欄として並べる。大臣・副大臣の経験は任命であり行動ではないので判定に使わない（0014の役職と行動の区別）。
2. **議員連盟「名簿に載っている」**：公表名簿・政治資金収支報告書・会議録のいずれかに出典URLのある行（`data/acquired/diet-leagues/memberships.csv`）。分野（その議連が推進する所管）が空の行は載せない。
3. **同じ分野の団体との金銭の関係**：政治資金の関係団体で、受けた寄附・パーティー対価の合計が議員×団体で100万円以上。団体の分野は審議会の発言記録（原本照合済み）に出た所管省庁で決める。個人の寄附者は扱わない。
4. **運動団体・ロビー活動の立場**：業界団体・運動団体・メディア（業界としての要望のみ）・議連・自治体・労働団体の、声明・要望・陳情・ヒアリング出席・審議会委員・意見公募への意見・署名運動を、出典URLつきで記録し、法案の結果（台帳にある＝成立）に結ぶ。立場は「推進」「反対」だけ。

## 印の文言（事実だけ）

「分野との継続的な関わり（族議員の機械判定）」「議員連盟の名簿に載っている」「同じ分野の団体と金銭の関係が記録されている」。不正・癒着・利権とは書かない。

## 据え置く欠測（正直に出す）

- 議連の名簿は未取得（初回は表が空で、summary.json の「入力が空の表」に出る）。取り込みの手順は各 README。委員会の委員・理事は、委員会の審議の取り込み（`data/acquired/committee-deliberation/`）から参考欄にだけ出す（下の追記）。
- relations.csv（政治資金）は Git に無い。`--relations` で渡したときだけ金銭の欄が埋まる。
- 衆法・参法は分野に入らない。

## 認知の罠

分野に長くいる＝推した、ではない（委員長は持ち回りが多い。だから A は2回次以上、B は行動の本数と年数で別に測る）。金銭の関係＝見返り、ではない。メディアは論調ではなく業界としての要望だけを見る。

## 追記（2026-10-29）：委員会の出席・理事は参考欄にだけ出す（判定に入れない）

- 入力：`data/acquired/committee-deliberation/bill_committee_{衆議院,参議院}.csv` の「出席委員」「理事」。分野は上の判定と同じく閣法の所管（`ministry-v1/cabinet-bills.csv`）。
- 出力：`member-field-ties.csv` に2列。「分野の閣法の審議に出席した本数（参考。賛否ではない）」「分野の閣法の審議で理事を務めた本数（参考）」。数えるのは、その分野の閣法の委員会審議に1回でも出席した（理事として名のある）法律の本数。
- **出席は賛成でも承認でもない**。委員会の出席は割り当てと日程で決まり、出席した議員がその法案に賛成した記録ではない（賛否は採決の宣告や会議録の質疑に残る別の事実）。判定の基準にも印にも使わず、行がない議員×分野を増やさない（他の基準で行がある議員×分野に、参考の数が付くだけ）。
- 同姓同名は人物IDが会議録の名簿に無いので結ばない（推測で合算しない）。
- 認知の罠：出席が多い＝推した、ではない。理事は委員会の運営役で、持ち回りも多い。この2列を閾値にしたいときは、先に分布を見てこの記録を改める（結果を見て閾値を動かさない）。
