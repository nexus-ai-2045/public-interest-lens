# 設計決定0020：バックテストで「何を当てたら正解か」を決める（backtest-v1）

日付：2026-10-29。状態：採用（ねく 2026-10-29「バックテストはやりたい」「今の状況でやって、仕組みにして、実装が全部終わったらもう一回」）。評価方法設計書5章と設計決定0019の3を、測れる形に具体化する。計算式（method-spec-v2.3）は変えない。

## 決めたこと
1. **正解**：学術文献の事後評価（答えの分かっている事例集）のうち、原文と数値が一致した49件。ラベル（識別の強さ・結果指標の種類・便益の向き・研究の国）は2系統が独立に付け、一致したものだけ採用する。割れたものは保留にして採点から外し、数を公開する。一般書・報道は使わない。
2. **予測**：現行の計算が出す、その政策に当たる法律の向き（loss＝国賊側、benefit＝国士側）。どの法律を当てるかは、結果を見る前に年表と題名の語で固定した（`data/evidence/backtest_mapping.json`）。同じ政策に複数の法律があれば多数決。同数は当たりに数えない。
3. **精度の定義（本命 L0）**：「向きの一致率」＝ 正解の向きと現行の計算の向きが同じだった割合。採点の対象は、識別が強い（差の差・操作変数・RCT・合成対照）／日本の研究／結果が生産か雇用（現行の指標＝産業の付加価値と同じ向きで読める）／研究の対象がその法律の出来事そのもの／正解の向きが定まる、をすべて満たす事例だけ。
4. **合格**：一致率 **95%以上**、かつ採点の件数が **10件以上**（設計書5.3）。10件未満は「判定不能」と書き、95%に届いたとも届かないとも言わない。一致率には Wilson の95%区間を併記する。
5. **条件を緩めた参考（L1・L2）**：本命の件数が足りないとき、条件を緩めた数字も必ず並べる（良く見える方だけを選ばない）。L1＝識別が中程度まで許す／出来事が同じ政策分野でもよい。L2＝日本の研究で法律と結べて向きが定まるもの全部（価格・余剰も便益の向きに直す）。本命が判定不能でも、L1・L2が低ければそのまま書く。
6. **額の誤差・予測区間が正解を含む割合**（設計書5.1の的中率）：正解が指標ごとの効果（生産性が年1.6%上がった等）で、現行の計算が出す法律ごとの円の額と単位・範囲が違い、円に直せる件数が0。v1は「測れない」と書く。暫定の区間を出す計算（理論値・他国実績の区間）が入った測定から測る。
7. **届かない種類は暫定値を出さない**（設計書の方針のまま）。v1では暫定の区間自体が無いので、この決定で新たに止めるものは無い。
8. **固定と再測定**：結果は `data/evidence/backtest/<名前>.json` に、入力のハッシュ（事例・対応表・法律の配布データ）と計算式の版つきで固定する。v1＝実装が全部終わる前の1回目。実装後の2回目は `python3 scripts/backtest.py --snapshot v2 --date <日付>` を回すだけ。CI は毎回、今のデータで測り直し、入力が固定時と同じなら固定した結果と完全に一致することを検査する。

## 限界（結果と一緒に出す）
- 現行の計算の「向き」は、全産業や産業の付加価値を比較国の中央値と比べた結果論で、その法律だけの効果ではない（確かさは「参考」）。正解は特定の集団・指標への効果。向きが合う・合わないは、計算の良し悪しだけでなく「同じものを測っていない」ことも含む。
- 法律との結び付き（link）と対応表は、事例ごとの判断。結びの強さ（出来事そのもの／同じ分野）は系統1だけが付けた。
- 事例は49件、日本の法律に当たるのは一部。件数が少ないので、一致率は目安にすぎない。
- 書誌訂正つきで一致した3件（航空・金融ビッグバン・米国通信）は、事例集の集計（49件）に合わせて v1 では使っていない。

## 認知の罠（この測定の）
- 都合の良い絞り込み：本命の条件は結果の前に固定し、緩めた数字を並べる。件数が少ない結果を「当たった」と言わない。
- 件数の罠：10件未満の100%・0%は判定に使わない。
- 測れないものを測れたことにしない：額・区間は「測れない」と書く。

## 次
実装（理論値・他国実績の区間、産業連関）が済んだら、同じ仕組みで2回目を測り、v1との差を書く。事例を足す（書誌訂正つき3件・推定値一覧の識別の強い行）と本命の件数が増える。

## 追記：v1.1（2026-10-29、研究の結果指標と計算の指標をそろえる）
v1 の予測は法律ごとの総合の向き（全産業か産業の付加価値の結果論）だった。研究が見ている集団・指標と同じものを測るため、v1.1 は次を足した。v1 の結果は残してある。

1. **指標の対応表**（`data/evidence/backtest_alignment.json`）：日本の研究ごとに、研究の結果指標が計算の指標（`indicator-map.csv`）のどれと同じかを、same（同じ集団・同じ量）／proxy（同じ産業や分野だが集団や量が違う）／none（計算に同じ指標が無い）で付ける。2系統（私とHaiku）が独立に付け、一致した分だけ使う。割れたものは保留。
2. **予測**：対応した指標で、その政策に当たる法律の影響の判定（`impact.csv`の段階1〜3）の向き（貢献・上昇＝+1、悪影響・低下＝-1）の多数。計算が判定を出していない（保留・比較群なし・系列なし）事例は、外れとは数えず「止まった理由」に回す。
3. **段**：M0（本命）＝識別が強い／日本の研究／same／判定あり。M1＝識別が強いか中程度／same か proxy。M2＝same か proxy の全部。合格の線と件数の下限はv1と同じ。
4. **同じものを測れない分を外れに数えない**：v1の「合わなさ」には指標違いが混ざっていた。v1.1はそれを分けて、「計算に同じ指標が無い」件数と結果指標の種類を出す。足すべき指標の一覧になる。

v1.1 の結果は、M0 が0件、M1・M2 が1件（大店法、研究は改善・計算は悪影響で逆）で、どれも判定不能。日本の研究で法律と結べた14件のうち、10件は計算に同じ指標が無く（価格・余剰5、集団別の雇用3、その他2）、3件は対応が保留だった。本命を10件にするには、事例を足すだけでは足りず、計算側に指標（集団別の雇用・賃金、価格）を足す必要がある。
