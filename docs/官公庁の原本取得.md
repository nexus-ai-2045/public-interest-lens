# 官公庁の原本取得（クラウドから直接）

2026-10-17 から、クラウド環境で次の4つに curl で直接届く。ほかの go.jp（衆参・裁判所・各省）はまだ環境の通信設定で断られる。

| 相手 | 届くか | 使い道 |
|---|---|---|
| laws.e-gov.go.jp（法令 API v2） | 届く | 条文の原本照合 |
| kokkai.ndl.go.jp（会議録 API） | 届く | 議員の発言・審議の一次資料 |
| sdmx.oecd.org | 届く | 国際統計 |
| api.worldbank.org | 届く | 各国 GDP |
| www.shugiin.go.jp / www.sangiin.go.jp / www.courts.go.jp / www.mhlw.go.jp / www.cao.go.jp / www8.cao.go.jp / www.soumu.go.jp / www.mlit.go.jp | 断られる（403） | 規制改革要望・判決・予算の原本照合は、許可が入ってから |

## 相手への負荷

会議録 API は1本ずつ順番に、1リクエストごとに約1秒あける。失敗したら間隔を倍にして3回まで取り直す。

## 注意

- e-Gov が返すのは現行の条文。制定当時の文言ではない。条番号が改正で動いたもの（航空法第132条→第132条の85、著作権法第47条の6→第47条の5）は、現行の番号で照合した。
- 会議録の氏名は表記どおりに検索するので、同姓同名の別人が混ざる可能性がある。表記ゆれ（ひらがな表記など）で0件の人は保留にした。
- 賛否の系統A は言い回しだけを見るので、質疑だけの人はほぼ「中立」になる。系統B の読み手が批判的な質疑を別の向きに読むと不一致になり、保留に回る。
- 判例ページ（courts.go.jp）はクラウドの curl・WebFetch とも届かない。Mac の Chrome で裁判例検索を使う。検索結果は画面の中で描かれるので、同じページの iframe に `/hanrei/search1/index.html?query1=…&filter[judgeDateMode]=2&filter[judgeGengoFrom]=…#searched` を開き、数秒待って結果の行を読む（言葉だけだと2,000件を超えるので、裁判年月日の範囲で絞る）。詳細ページは fetch と DOMParser で dt/th の次の要素を読む。下級審で結果欄の無いものは、判決 PDF を pdf.js で読んで主文を取る。読んだ値は `data/acquired/court-rulings/lines/系統E_判例ページの抜き書き.md`。
