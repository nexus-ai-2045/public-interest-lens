# 自動更新と出典チェック

毎日1回、定期実行の Claude が `scripts/daily_update.py` を回し、変化があれば PR を作って検査を通し、main に取り込む。main に入るとサイト（Vercel）が自動で作り直される。

## 毎日の流れ

```
python3 scripts/daily_update.py --all --delete-merged-branches
```

| 段階 | 中身 | 落ちたとき |
|---|---|---|
| 取得 | 衆議院 議案情報（直近の回次）、e-Gov 施行日、OECD 表6、世界銀行、国会会議録の会議一覧 | 届かないサイトは「届かない」と記録して飛ばす。0 や空で埋めない |
| 振り分けの確認 | 成立法のうち、AI の振り分け（2系統）がまだ無いものを一覧にする | 定期実行の Claude が系統1・系統2を別々のサブエージェントで付け、一致したものだけ使う（ADR 0007） |
| 再計算 | `app/scripts` の判定ルール：振り分け v2 → 影響 → 損失 → 便益と公開判定 | 1つでも落ちたら公開ランキングは作らない |
| 公開ランキング | 公開可の法律は全件公開（2026-10-17 の常時承認）。承認日は公開の組が変わった日にだけ進む | — |
| 出典チェック | 下の節。不一致の法律は公開から外し、理由 SOURCE の保留に移す | 外した法律は翌日も照合し直し、直れば公開に戻る |
| 検査 | `pytest`、画面のテストとビルド | 赤なら PR を取り込まない |
| 片付け | `git worktree prune`、14日より古い作業フォルダ、main に取り込み済みで2日以上動きのない `claude/`・`report/` ブランチ | — |

記録は `.local/daily-update/<日付>/report.md`（Git に入れない）。PR の本文にこの表を貼る。

## 出典チェック（ファクトチェックの中心）

`scripts/source_check.py`。判定ルールの TypeScript を使わず、元の表だけから Python で別に計算し直して、公開している数字を1つずつ突き合わせる。結果は `data/derived/source-check/check.csv`（項目ごと）と `summary.json`（件数と外した法律）に残し、Git に入れて誰でも確かめられるようにする。

| 項目 | 突き合わせる相手 |
|---|---|
| 出典URL | 官公庁・国際機関のドメインだけか。台帳（衆議院の経過、e-Gov の改正履歴）に記録された URL と同じか |
| 題名 | 衆議院の議案台帳 |
| 施行日 | 施行日台帳。施行期日の原文があるか。公布日（議案台帳の和暦を西暦に直した日）より前でないか |
| 名目付加価値 | 損失表に書いた「開始前最後の年」の値と OECD 表6 の値 |
| 額（中央値・幅） | 公開値の比較国・窓・産業で、OECD 表6 の連鎖実質から計算し直した額（1円まで一致） |
| 原本のハッシュ | 取得記録の原本が手元にあるとき（Mac）だけ。クラウドには原本が無い |

「対象外」（OECD 表6 以外の指標で再計算が未対応、測った便益を差し引いた純額）は外さずに件数を出す。対応する指標を増やしたら、この節とテストを更新する。

評価は行動（提出・採決・質問・所管）と結果だけを使う。公約や発言の中身では点を付けない。

## 一次資料に届かないとき

クラウドの環境は今、go.jp・OECD・世界銀行に届かない（取得の段階が「届かない」になる）。正しい経路は次の順。

1. **クラウドの環境で取得先のドメインを許可する（おすすめ）**。プロジェクト設定 → クラウド環境 → ネットワークで、`shugiin.go.jp`、`sangiin.go.jp`、`laws.e-gov.go.jp`、`kokkai.ndl.go.jp`、`sdmx.oecd.org`、`api.worldbank.org` を許可する。Mac は要らなくなる。
2. 許可できない間は、Mac の Claude が決まった1つのフォルダに取得だけをする。Mac ではワークツリー・クローン・ブランチを作らず、コミットも push もしない。クラウド側が `--incoming <そのフォルダ>` で取り込み、クラウドの `claude/` ブランチからだけ push する。フォルダの中身は `data/acquired/<task-id>/*.csv` と同じ形（原本は `<task-id>/raw/`）。
