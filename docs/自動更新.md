# 自動更新と出典チェック

毎日1回、定期実行の Claude が `scripts/daily_update.py` を回し（最初に `scripts/preflight.py` の事前チェックで止まる原因を測る。設計決定0010）、変化があれば PR を作って検査を通し、main に取り込む。main に入るとサイト（Vercel）が自動で作り直される。

## 毎日の流れ

```
python3 scripts/daily_update.py --all --delete-merged-branches
```

| 段階 | 中身 | 落ちたとき |
|---|---|---|
| 取得 | 衆議院 議案情報（直近の回次）、e-Gov 施行日、OECD 表6、世界銀行、国会会議録の会議一覧 | 届かないサイトは「届かない」と記録して飛ばす。0 や空で埋めない |
| 振り分けの確認 | 成立法のうち、AI の振り分け（2系統）がまだ無いものを一覧にする | 定期実行の Claude が系統1・系統2を別々のサブエージェントで付け、一致したものだけ使う（ADR 0007） |
| 再計算 | `app/scripts` の判定ルール：振り分け v2 → 影響 → 損失 → 便益と公開判定 | 1つでも落ちたら公開ランキングは作らない |
| 公開ランキング | 公開可の法律は全件公開（2026-10-17 の常時承認）。承認日は公開の組が変わった日にだけ進む | — |
| 出典チェック | 下の節。不一致の法律は公開から外し、理由 SOURCE の保留に移す | 外した法律は翌日も照合し直し、直れば公開に戻る |
| 議員ページ | `scripts/build_public_members.mjs` で同じ派生データから作り直し、出典チェックで照合する | 不一致があれば取り込まない |
| 検査 | `pytest`、画面のテストとビルド | 赤なら PR を取り込まない |
| 片付け | `git worktree prune`、14日より古い作業フォルダ、main に取り込み済みで2日以上動きのない `claude/`・`report/` ブランチ | — |

記録は `.local/daily-update/<日付>/report.md`（Git に入れない）。PR の本文にこの表を貼る。

## 全ページを同じデータにそろえる

公開データ（`app/public/distribution/` の ranking.json・members.json・laws.json・laws-detail/）の作り直しは、`python3 scripts/rebuild_public.py` の1本だけで行う。毎朝の更新もこれを呼ぶ。手で額や関与の表を直したときも、これを回して出たファイルを全部コミットする。

`tests/test_public_sync.py` が、各ファイルに記録した入力の照合値（SHA-256）がいまの派生データと同じか、/ranking・/members・ranking.json の本数がそろっているかを確かめる。1つでも古いと検査が落ち、PR は取り込まれない。main に入ると Vercel が作り直すので、全ページが同じ段階のデータを出す。

## 出典チェック（ファクトチェックの中心）

`scripts/source_check.py`。判定ルールの TypeScript を使わず、元の表だけから Python で別に計算し直して、公開している数字を1つずつ突き合わせる。結果は `data/derived/source-check/check.csv`（項目ごと）と `summary.json`（件数と外した法律）に残し、Git に入れて誰でも確かめられるようにする。

| 項目 | 突き合わせる相手 |
|---|---|
| 出典URL | 官公庁・国際機関のドメインだけか。台帳（衆議院の経過、e-Gov の改正履歴）に記録された URL と同じか |
| 題名 | 衆議院の議案台帳 |
| 施行日 | 施行日台帳。施行期日の原文があるか。公布日（議案台帳の和暦を西暦に直した日）より前でないか |
| 名目付加価値 | 損失表に書いた「開始前最後の年」の値と OECD 表6 の値 |
| 額（中央値・幅） | 公開値の比較国・窓・産業で、OECD 表6 の連鎖実質から計算し直した額（1円まで一致） |
| 議員ページ | 法律の額が公開ランキングと同じか。証拠URLが国会会議録・衆参の議案情報だけか。個人の配分の合計が額×帰属率を超えないか |
| 原本のハッシュ | 取得記録の原本が手元にあるとき（Mac）だけ。クラウドには原本が無い |

「対象外」（OECD 表6 以外の指標で再計算が未対応、測った便益を差し引いた純額）は外さずに件数を出す。対応する指標を増やしたら、この節とテストを更新する。

評価は行動（提出・採決・質問・所管）と結果だけを使う。公約や発言の中身では点を付けない。

## 評価ループ（毎日、2026-10-17 から）

全3,415本に額か理由を付けたうえで、AI の判定が要る法律を毎日少しずつ決め、誤りの型から判定ルールを直す。ループは5段で、小さい順に回る。

| 段 | 誰が | 何を直すか |
|---|---|---|
| 1 | Haiku（2系統、互いの結果を見ない） | 1本ずつ判定し、出力の形を自分で確かめる |
| 2 | Sonnet（Haiku 約10本ごとに1つ） | 2系統の食い違いを決める。同じ迷いが続けば木のプロンプトを直す |
| 3 | Opus | 分野をまたいだ一貫性を見て直す。見つけた誤りの型を返す |
| 4 | 定期ルーチンの Claude | 誤りの型を `docs/学習記録/` に記録する。2回以上出た型は判定ルール（スクリプト）とテストにする（例：同じ題名の改正は分野をそろえる `align_by_title`） |
| 5 | 毎日の自動更新 | 出典チェックの不一致と、翌日の queue.json の残りを次の入力にする |

手順：

1. `daily_update.py` が `.local/daily-update/<日付>/queue.json` を書く。中身は「振り分けの決着」（A・B が割れて種類か分野が空の法律）、「分野ラベル」（全体指標の額で、どの分野も無く全産業にしている法律）、「系統の決着」（v2 の2系統が食い違って保留のまま、第3の判定者の記録も無い法律）、「出典チェックの不一致」。
2. `python3 -m scripts.eval_loop prepare --out <作業フォルダ>` でバッチを作る。表示される n を木に渡す。
3. Workflow で `scripts/workflows/triage-tiebreak-tree.js`（args：dir＝作業フォルダ/tiebreak、spec＝data/derived/bill-triage-v1/spec.md の絶対パス、n）、`scripts/workflows/ai-field-tree.js`（args：dir＝作業フォルダ/field、n）、`scripts/workflows/triage-lines-tree.js`（args：dir＝作業フォルダ/lines、specs＝[data/derived/bill-triage-v2/spec.md、data/derived/bill-triage-v1-line2/criteria.md、data/derived/bill-triage-v1-line2/criteria-v2-fields.md の絶対パス]、n）を回す。系統の決着は新分野を含む v2 の基準で判定する。
4. 結果を `python3 -m scripts.eval_loop apply-tiebreak <結果.json>` ・`apply-field <結果.json>`・`apply-lines <結果.json> <作業フォルダ>/lines/inputs.json`（prepare が書いた、判定に渡した入力の指紋）で取り込み（取り込みで規則 L1 を当てる：要約の無い一部改正で評価対象・実質改正の系統を採った決定は保留に戻す。`apply-lines` で直接取り込んだ決め方「一致」は2系統の証跡が無いので保留に落とし、一致を採用するのは 5 の `verify-lanes` → `apply-candidates` だけ）、`daily_update.py --rebuild --test` を回し直す。
5. Opus が返した誤りの型を `docs/学習記録/<日付>.md` に書く。前の記録と同じ型なら、ルールにしてテストを足す。

### Grok の file-backed 移管

`scripts/workflows/` の3つの木は Claude の Workflow で、Haiku、Sonnet、Opus を名指しする。Grok へ移すときは、その名前を置き換えて木を実行したことにしない。`pack` は判定も agent の起動もしない。

1. `python3 -m scripts.eval_loop prepare --out <作業フォルダ>` でバッチを作る。試験だけ `--fixture tests/fixtures/eval-transport/queue.json` を付ける。この fixture は架空の id で、本番の表は読まない。
2. `python3 -m scripts.eval_loop pack --work <作業フォルダ>` で、各バッチの snapshot、原本の sha256、2系統の結果ファイルの位置、file-backed packet を `<作業フォルダ>/transport/` に書く。packet の `launched` は false で、`human_gate` は親が配るまで待つ。
3. 親が、同じ snapshot を互いに見せない2つの実 session へ packet を渡す。各 session は `eval-lane-v1` の JSON を、packet の `expected_output_path`（作業フォルダからの相対パス）へ書く。`provider` は `grok`、`session_id` は実行した session、`lane` は `a` または `b`、`input_sha256` と系統の決着では `inputs_sha256` を packet の値のまま書く。
4. `python3 -m scripts.eval_loop verify-lanes --work <作業フォルダ> --kind field|tiebreak|lines --batch <b000 など> --lane-a <結果> --lane-b <結果> --candidate <候補.json>` で、同じ入力 hash に対して決定の値が一致し、両方に理由がある行だけを現行 apply の labels 形にする。決め方は「一致」だけである。
5. `python3 -m scripts.eval_loop apply-candidates --work <作業フォルダ> --kind <同じ kind> --batch <b000 など> --candidate <候補.json> [--inputs <作業フォルダ>/lines/inputs.json] [--dest <表.csv>]` で取り込む。候補の kind、batch、`input_sha256`、`inputs_sha256` が manifest と一致し、snapshot、source、系統の決着では `lines/inputs.json` も pack のときと同じバイトのときだけ、既存の apply を呼ぶ。違うときは終了コード 2 で、`--dest` も本番の表も書かない。系統の決着は規則 L1 を既存の `apply-lines` で当てる。`--dest` を省くと本番の表へ書く。

壊れた JSON、件数の過不足、同じ session の二重使用、同じ結果ファイル、pack より後に変わった入力は、verify が候補を残さず終了コード 2 で止まる。apply も、候補の hash または今の snapshot、source、inputs が manifest と違うときは終了コード 2 で表を書かない。候補が Workflow の `result` も持つとき、および同じ id の題名が複数のバッチで違うときは、終了コード 2 で `--dest` も本番の表も書かない。不一致、根拠なし、候補外の値は、その行だけを保留にし、0 や空の分野や「経済全体」へは埋めない。`fake` は試験用の provider で、実 Grok の分類ではない。

prepare をやり直す、batch の source が変わる、または `lines/inputs.json` のバイトが変わるときは、古い packet と古い候補は今のファイルと合わない。pack をやり直してから、新しい hash の packet で 2 session をやり直す。code を統合しただけでは、batch のバイトが同じなら hash は変わらない。

AI の判定は分野・種類を選ぶことだけに使う。額は公的統計から機械的に計算し、AI で数を作らない。

## 一次資料に届かないとき

クラウドの環境は今、go.jp・OECD・世界銀行に届かない（取得の段階が「届かない」になる）。正しい経路は次の順。

1. **クラウドの環境で取得先のドメインを許可する（おすすめ）**。プロジェクト設定 → クラウド環境 → ネットワークで、`shugiin.go.jp`、`sangiin.go.jp`、`laws.e-gov.go.jp`、`kokkai.ndl.go.jp`、`sdmx.oecd.org`、`api.worldbank.org` を許可する。Mac は要らなくなる。
2. 許可できない間は、Mac の Claude が決まった1つのフォルダに取得だけをする。Mac ではワークツリー・クローン・ブランチを作らず、コミットも push もしない。クラウド側が `--incoming <そのフォルダ>` で取り込み、クラウドの `claude/` ブランチからだけ push する。フォルダの中身は `data/acquired/<task-id>/*.csv` と同じ形（原本は `<task-id>/raw/`）。
