# 共通指示（判決・行政訴訟の収集）

目的：日本で事業や技術を制限した規制（法律・政令・省令・告示・行政処分・行政指導・刑事規定の運用）が、裁判で違法・違憲とされた例、または争われた例（規制側が勝った例も含む）を、一次資料で確かめて記録する。ファクトチェック用なので、確かめられないことは書かない。

## 調べ方
- WebSearch で探し、WebFetch で一次資料を開いて確かめる。一次資料は裁判所の判例ページ（https://www.courts.go.jp/hanrei/<番号>/detail2/index.html 等）、省庁・自治体の公表資料、e-Gov 法令、国会会議録。
- 判決日・事件番号・法廷・結果は、必ず courts.go.jp の判例ページを WebFetch で開いて読んだ値だけを書く。開けなかったら "未確認" と書く。
- 報道・Wikipedia・法律事務所のブログは手がかりとしてだけ使い、値の根拠にしない。
- 記憶だけで値を書かない。URL は自分が実際に WebFetch で開けたものだけを書く。
- bash で curl しても政府サイトには届かない。WebSearch / WebFetch を使う。
- mcp__hearthbot__ で始まるツールは使わない。git 操作もしない。

## 出力
指定された JSON ファイルに、次の形の配列を Write ツールで書く（UTF-8、日本語）。

```json
[
  {
    "id": "指示で渡されたID",
    "通称": "事件の通称",
    "規制": "争われた規制（法令名と条文、処分名）",
    "所管": "規制の所管（省庁・自治体）",
    "分野": "産業・技術の分野",
    "争点": "何が争われたか（1〜2文）",
    "裁判所": "例：最高裁判所第二小法廷",
    "判決日": "YYYY-MM-DD または 未確認",
    "事件番号": "例：平成24(行ヒ)279 または 未確認",
    "裁判種別": "判決／決定",
    "結果": "判例ページの結果欄どおり（例：棄却）",
    "規制への判断": "違憲／違法・無効／処分取消／差止認容／無罪（規制の適用を否定）／合憲・適法（規制維持）／侵害認定（技術側が敗訴）／その他",
    "判断の要旨": "判示事項・判決要旨を短く（原文の言葉を優先）",
    "その後の変化": "判決後の法改正・告示改正・運用変更（法令名と公布日・施行日）。確かめられなければ 未確認",
    "判例URL": "courts.go.jp の判例ページ",
    "関連URL": ["省庁の談話・通知・改正法など、開けた一次資料のURL"],
    "確認状況": "確認済み（判例ページで日付・番号・結果を読んだ）／一部未確認（どこが未確認か）",
    "備考": "下級審の経過、注意点など"
  }
]
```

1件ごとに完結させ、見つからない事件も "未確認" を入れて出す（消さない）。
