# 委員会の審議（成立した法律ごと）

取得元：国会会議録検索システム API（https://kokkai.ndl.go.jp/api/meeting）。法律の付託委員会・付託日・議決日は `data/acquired/bill-census-full/enacted.csv`（衆議院の議案情報）。
作り方：`scripts/fetch_committee_deliberation.py`（fetch → build）。API の原本は Git に入れず、ここには抜き出した結果だけを置く。

| ファイル | 中身 |
|---|---|
| bill_committee_衆議院.csv・bill_committee_参議院.csv | 法律×院ごとの1行。会議数、初回・最終の会議日、委員長、理事、出席委員（「氏名(出席した会議数/会議数)」を `;` で並べた委員名簿）、採決日・結果・方法・宣告の抜粋、修正案の宣告数、附帯決議の有無 |
| meetings.csv | 法律に紐づく会議（号）の一覧。議題の紐づけは、冒頭の「本日の会議に付した案件」に法案名があれば `header`、委員長の議題宣告から拾ったら `agenda`。併せて議題の案件数・発言数・参考人質疑の有無（会議録のURLは `https://kokkai.ndl.go.jp/txt/<会議ID>`） |
| amendments.csv | 委員会での修正案。筆頭提出者（委員長提出はその委員長）と人数、趣旨説明者、宣告と趣旨説明の抜粋、委員会での可否、発言URL。「外N名」の残りは会議録に名前が出ない |
| resolutions_衆議院.csv・resolutions_参議院.csv | 附帯決議。趣旨説明の発言（案文の朗読を含む本文、最大3,000字。一括して議題になった法律は1行にして法律IDを `;` で並べる）、決議の宣告、政府の所信の抜粋、発言URL |

## 限界（確かめた範囲）
- 委員名簿は「会議に出席した委員」の和集合。委員会の所属委員の全員ではない（一度も出席しなかった委員は入らない）。
- 法案名で会議を探すので、法案名が似た別の法案（例：「…法律」と「…法律の施行に伴う関係法律の整備等に関する法律」）の会議も、冒頭の案件欄に法案名が含まれれば紐づく。
- 取った API の応答は、外部資料として `.local/external-materials/committee-deliberation/` に登録する（取るたびに自動。内容は unverified。登録前に取った分は `register` で登録し直す）。
- 修正案は、法案ごとの議事の区間（議題の宣告から次の案件まで）に限り、宣告ごとに提出者を1件ずつ取る。趣旨説明者と採決の可否は、提出者の名前で対応が確かなものだけ付け、確かでなければ空（採否不明）のまま。法案名を挙げた宣告は、その法案のものだけ取る。
- 修正案の提出者を議員の鎖（関与の一覧）に足すときは、会議録から機械で取った段階では「候補」で、算入=いいえ。独立した2系統が個人への帰属を確かめた行だけを `amend-confirmed.csv`（法律ID・院・氏名・系統A・系統B、両方「確認」）に書くと、可決された修正案の分が算入=はいになる（AGENTS.md、ADR 0007）。確認の作業はロードマップ R56 の続き。
- 修正案・附帯決議は会議録の言い回しで抜くので、言い回しが違う年代のものは漏れうる。漏れは「なし」と読まず、`修正案の宣告数` と法律の議決結果（修正）を突き合わせて確かめる。
- 審査省略（委員会に付託されなかった）の法律・院は行が空（会議数0）。

## 取り込みの状況
名義検査が1回の PR で足せる行の量に上限を置くため、bill_committee_*・resolutions_* は後続の PR で順に足す（足し終えたらこの節を消す）。
