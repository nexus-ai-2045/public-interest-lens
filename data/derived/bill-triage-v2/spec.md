# bill-triage-v2：題名による分野・指標の固定規則

承認された `docs/提案/指標の選び方-v1.md` の3（指標）と4-4（D1〜D5）を適用します。元のAI判断を入力列に残し、規則適用後の値と区別します。

## 入力と規則

対象は `data/acquired/enforcement-dates/enforcement.csv` の施行日が空でない行（作成時170本、2026-10-17 の追加取得後197本、その後の取得で349本中281本）。系統1は `bill-triage-v1/triage.csv`、系統2は `bill-triage-v1-line2/labels.csv` の題名・種類・分野を入力にします。第1条、委員会、統計値は分野選択に使いません。

- D1：全8分野の語を題名から探し、題名の最初の位置にある語の分野に決め直します。AIの入力分野や語表の分野順を優先しません。語が無ければ対応表なし。指標の選択順（表の上から）とは別です。
- D2：「及び〜設置法」「及び〜整備法」を除いた最初の法律で判断します。
- D3：新設法人の根拠法は組織手続から新規へ修正します。
- D4：機構法などの一部改正は組織手続から実質改正へ修正します。
- D5：種類・入力分野が未定義、または最初の語の位置に異なる分野が重なる場合は保留です。承認文書に同位置の競合を解く優先順位は無いため、v2.1 より前は推測せず保留にしていました（下の「保留の内訳と解消規則（v2.1）」で、語の長さだけで機械的に解ける場合を HR1 として足しました。解けない競合は D5 のまま保留です）。
- 指標：決まった分野の表を上から当て、最初の一致行、または分野の既定値を使います。

語表 `FIELD_WORDS` は従来の系統2基準・指標表と、170本を見て追加した語を含みます。金融「社債・振替・割賦・信託・再生」、交通「交通・移動」、観光「ツーリズム」、行政「データ活用」などの追加は学習内の調整です。未知の法律に対する妥当性は未検証です。

## 全法律への拡張

全3,415本の結果の一覧は `data/derived/all-laws-v1/`（`spec.md`）。この版の振り分け・影響・損失・便益の対象は、これまでどおり施行日台帳に施行日が入っている行です。台帳に行が足されると系統1は自動で載り、系統2のラベルが無い行は影響の段で保留になります。`bill-triage-v1-line2/labels.csv` が全3,415本を持っていても、この版は受け付けます（`labels-line2.csv` は labels.csv と同じ行数になります）。

- `labels-line1.csv`：TypeScript `app/src/indicator-pick.ts` の適用結果。
- `labels-line2.csv`：Python `scripts/triage_v2_line2.py` の適用結果。
- `agreement.csv`：施行日のある全行を保持。両系統とも定義済みの判定で、判定・分野・指標が一致した場合のみ採用します。両系統が保留でも採用しません。v2.1 から末尾に「解消規則」（HR1〜HR4。使っていなければ空）と「食い違いの区分」（一致しなかった行の解消前の区分）の列を足しました。

影響表から除くのは、両系統が明示的に評価対象外で一致した行だけです。系統欠落、保留、食い違いは影響表へ残し、段階と向きを採用しません。後段の損失・便益・公開候補へは進みません。

### 規則（すべて題名と2系統の出力だけで決まる機械的な規則）

各系統の振り分けの中（TypeScript `app/src/indicator-pick.ts` と Python `scripts/triage_v2_line2.py` の両方）：

- HR1：題名の最初の位置に別々の分野の語が重なったら、同じ位置の語のうち「ほかの語の一部になっている短い語」を除く。残る語の分野が1つなら、その中で最長の語の分野を採る（例：「電子」は「電子消費者契約」の一部、「再生」は「再生可能」の一部）。残る語が複数の分野にまたがるなら解けないので D5 のまま保留とし、競合した分野と語を理由に書く。既存8分野の語どうしにも、新分野の語どうしにも同じ規則を当てる。
- HR2：D4 と同じ条件で、題名が「…機構／公庫／公団／事業団／基金／銀行／金庫法**等**の一部を改正する法律案」の組織手続を実質改正に直す。設置法を含む題名は直さない。

2系統の出力を比べる段階（TypeScript `app/src/line-agreement.ts` の `resolveTriageDiff`、Python `scripts/triage_v2_line2.py` の `resolve_diff`。v2 の runner が題名を渡したときだけ働き、v1 は変えない）。両系統とも評価対象／評価対象外のときだけ使う：

- HR3：同じ分野で指標だけ違い、判定が同じなら、分野ごとの固定の指標の優先順（指標の表の上の行ほど先、既定値は最後）で先のものを採る。例：金融は 不良債権比率（F1）→ 企業倒産件数（F2）→ 貸出残高（既定）、交通・移動は 就業者数（T1）→ 旅客輸送の付加価値（T2）→ 利用件数（T3・既定）。表にない指標や判定も違う場合は解消しない。
- HR4：片方が対応表なしで、もう片方が既存8分野のFを名指すとき、2系統の種類が同じで、題名（最初の法律）に分野Fの語表の語（直接の語）が含まれるときだけFを採る。指標はFの表を題名に当てて決め、判定は種類から決め直す（定型改正・組織手続は評価対象外、それ以外は評価対象）。題名に語が無い、種類が違う、種類が不明なら解消しない。

解消した行は `agreement.csv` の「解消規則」に規則id、「理由」に解消の内容、「食い違いの区分」に解消前の区分が入ります。各系統のラベルの「規則」「理由」列にも HR1／HR2 が残ります。解消できない行は 保留 のままで、理由に「HR3に当たらない：指標も判定も食い違う」のように当たらなかった条件を具体的に書き、区分を付けます。

- TB2（第3の判定者、R2）：HR1〜HR4 で解消しない行と、片方が保留の行について、`tiebreak-lines.csv`（id・採用・決め方・理由）に、AI の第3の判定者の独立した2つの判定（Haiku 2系統）が一致して（決め方＝一致）「系統1」か「系統2」を選んだ記録があれば、その系統の判定・分野・指標をそのまま採る。新しい値は作らない。採る側が評価対象外か、評価対象で分野と指標がそろっているときだけ採用し、それ以外、「保留」、Sonnet や Opus が単独で決めた行（ADR 0007 の2系統の一致に当たらない）は保留のままで、翌朝の評価ループで再判定する。「一致」は Sonnet の申告ではなく、Haiku 2系統の選択をワークフローの中で機械的に比べて決める。記録には判定に渡した入力（系統1の値・系統2の値＝判定|種類|分野|指標|理由、概要の値＝何をする・狙いの sha256 先頭16桁）を、取り込む時点の表ではなく prepare が書いた `lines/inputs.json` から残し、どれかが今と違えば当てずに保留へ戻す。判定者は `scripts/workflows/triage-lines-tree.js`（Haiku 2系統→Sonnet→Opus）で、題名と国会会議録の提案理由の要約だけを材料にする。

HR1・HR2 は、4本の競合と1本の食い違いを見たあとで作った規則なので、この5本での確認は学習内です。一致の確認は規則の妥当性の証拠ではありません。HR3・HR4 は現データに該当が無く、合成した入力のテストでのみ確かめています。

## 版の保存先と再現

impact/loss/benefit の全runnerが `--triage v1|v2` または `TRIAGE_VERSION`（既定v2）を使います。指定した版の入力・出力を同時に選び、別版の直前の実行結果に追従しません。不正な版指定は拒否します。

| 計算 | v1保存先 | v2保存先 |
|---|---|---|
| 影響 | `impact-v1/` | `impact-v1-triage-v2/` |
| 損失 | `loss-v1/` | `loss-v1-triage-v2/` |
| 便益 | `benefit-v1/` | `benefit-v1-triage-v2/` |
| 公開条件判定 | `publish-v1/` | `publish-v1-triage-v2/` |

いずれも `data/derived/` 下。アルゴリズム版はv1のままで、振り分け版を別に示します。便益の系統2原資料 `benefit-v1-line2/labels.csv` は両版で共用し、欠落・不一致時は既存規則で保留します。公開条件の計算は公開実行ではありません。

## 新分野（field-expansion-v1）の取り込み

`docs/提案/分野の拡張-v1.md` の10分野の提案のうち、承認項目 B1・B2・B3・B4 の推奨を、`bill-triage-v2` の規則として足しました（`app/src/indicator-pick.ts` の `NEW_FIELD_WORDS` と `scripts/triage_v2_line2.py` の `_NEW_FIELDS`。同じ文書から別に書き起こした2実装で、`tests/test_triage_v2.py` が全3,415題名で出力の一致を確かめます）。

- **既存優先（B2）**：既存8分野の語が題名に1つでもあれば、これまでの規則（D1・D5）のまま。新分野の語は、既存の規則で「対応表なし」になる題名にだけ当てます。したがって既存の結果は、もとが「対応表なし」だった行を除いて変わりません（`tests/test_triage_v2.py` が全題名・全種類で、新分野の語を無効にした結果と比べます）。
- **新分野の決め方**：題名の最初の位置にある新分野の語の分野。同じ位置の語が別の語の一部（建築／建築士、土地／土地改良）なら長い語を採り、別々の分野の語が重なれば保留（D5）。D2（設置法・整備法を除く）は既存と同じ。
- **水道・廃棄物は作らない（B3）**。水道・下水道・廃棄物などの題名は、ほかの語が当たらなければ対応表なしのままです。
- **指標と代理（B4）**：新分野の指標は1分野1本（産業の付加価値）。直接の語に当たった法律は指標名そのまま、代理の語に当たった法律は末尾に「（代理）」を付けた別の指標にします（例：建設業の付加価値／建設業の付加価値（代理））。代理の指標は「参考」で、影響段階の向きは貢献・悪影響ではなく「上昇／低下」、損失額は参考フラグ付き（合計に入れず、公開せず、議員への配分に使わない）。教育・医療・福祉・住宅・不動産・文化・娯楽・生活サービスは代理の語しか無いので常に「（代理）」付きです。
- **対応表なしのまま残す主題（B5）**：司法・選挙・防衛・公務・年金・環境・防災・消費者など（提案の3-1）。
- **規則の符号**：`<分野>直接`／`<分野>代理`（例：`D1／建設直接`）。理由の文言は既存と同じ形です。
- **AI の入力分野**：系統の入力分野に新分野名（と対応表なし）を受け付けます。分野そのものは従来どおり題名の語で決め直します。定義にない値は D5 で保留。

## 独立性の限界

2実装の一致は書き起こしの誤りを検査できますが、規則の妥当性の証拠ではありません。分野・指標は同じ題名と規則から決まり、規則適用後の一致を独立したAI判断の一致と扱いません。元のAI判断は分野165/170、種類168/170の一致です。両系統は同系列モデルです。学習外データ、別モデル、因果妥当性の検証は未完了です。
