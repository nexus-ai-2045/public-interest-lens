# 抜き取り検証で不合格のまま残った法律の読み直し（2026-11-19）

初回の抜き取り検証（2026-10-30、`docs/評価の独立検証.md`）で不合格になり、額を参考値に下げる自動の規則にも当たらず「不合格のまま」残っていた 11 本を、一次資料から読み直して1本ずつ決着させた記録。

## 前提

- 対象：抜き取り 118 本のうち、初回が不合格で、台帳の検証状態が「抜き取り検証で不合格」だった 11 本。どれも付加価値の額が無い（保留 6、測定できない 4、国の収支の別欄 1）。順位・議員配分には初めから入っていない。
- 初回の判定表（`sample-verdicts.csv`）と初回の記録（`verification-raw/`）は書き換えない。
- 初回の読み手への指示文はリポジトリに残っていない。今回の定義は `prompt-v1.md` に書いたもので、初回と一字一句同じとは限らない。
- 新しく抜き取り直してはいない。同じ 118 本を今の台帳に当て直した。

## 手順

1. 読み手：1本につき2系統（計 22 件）。サイトの値も初回の判定も見せず、題名と資料の場所だけを渡した。系統Aは議案本文を先に、系統Bは会議録を先に読む。モデルは Haiku。指示文は `prompt-v1.md`（版 v1）。結果は `lineA.json`・`lineB.json`（判定、理由、原文の引用、読めた URL、読めなかった資料、確信）。
2. 資料：衆議院の議案本文（理由と条文）と国会会議録検索システム。読む道具は `scripts/fetch_law_source.py`。読めなかった資料は各行の「読めなかった資料」に残した。
3. 裁定：2系統は 11 本とも類型・経済に効くかの両方で一致した。初回と結論が変わった項目（5 本）と、照合の読み方（3 本に関わる）は、Opus が一次資料を自分で読んで裁定した。結果は `rulings.json`。
4. 決着：`python3 scripts/resolve_sample_failures.py` が、台帳・2系統の判定・裁定から規則で決めて `../sample-resolutions.csv` を書く（AI は呼ばない）。規則はスクリプトの冒頭にある。サイトの主張は到達点で読む（下の「照合の読み方」）。決着の行には、決着が前提にしたサイトの値（類型・分類・到達点・経済に効くか）を残し、台帳を作り直すときにサイトの値が変わっていれば決着を使わず不合格に戻す。
   - `sampling-time-ledger.csv` は、抜き取り時の台帳（#133 のマージ 275620d の `ledger.csv`）から対象 11 本の行だけを写したもの。抜き取り時と今で到達点が違う法律（閣法-180-38、閣法-180-72）は、決着が今の台帳に対するものだと理由に書く。
5. サイトの値の訂正：参考に下げた6本は、読み直しの値（2系統の一致、または裁定）を `data/derived/primary-source-corrections-v1/corrections.csv` に置いてサイトの値を直した（振り分けと経済の区分の AI の記録は書き換えない）。`scripts/build_all_laws_outcomes.py` と `scripts/build_evaluation_ledger.py` がこの表を読む。表の値が読み直しの記録と同じことは `tests/test_primary_source_corrections.py` が確かめる。
6. 反映（この順）：`python3 scripts/build_all_laws_outcomes.py` → `PYTHONPATH=. python3 scripts/build_macro_amounts.py` → `PYTHONPATH=. python3 scripts/build_three_columns.py` → `python3 scripts/build_evaluation_ledger.py build` → `python3 scripts/resolve_sample_failures.py` → `python3 scripts/build_evaluation_ledger.py build` → `python3 scripts/report_verification.py` → `python3 scripts/check_error_types.py`（同じ型の誤りの全件の検査、`../../error-type-check-v1/`）。

抜き取り 118 本の今の内訳：合格 51、参考に下げた 67（規則で自動）、不合格のまま 0。

経過：1回目（PR #203）は6本を「参考に下げた」（サイトの値が未修正）にした。2回目（同日）にサイトの値を直し、同じ読み直しの記録で決着を作り直して合格に戻した。読み手は読み直していない（記録は法律そのものの読みで、サイトの値を見ていないので変わらない）。

## 裁定の要点

- 照合の読み方：台帳の「分類＝評価対象外」は、市場の産業の対応表に当たらないという振り分けの区分で、「制度だけ」という主張ではない（裁定は閣法-180-72、閣法-217-48、衆法-218-1 を名指しして認めた）。1回目は名指しした法律にだけこの読み方を使った。2回目は、裁定の理由が振り分けの定義そのもの（法律ごとの事情ではない）なので、規則として「サイトの主張は到達点で読む」に改めた：到達点が評価対象外か効果なし（定例）ならサイトは制度だけと扱い、それ以外（額・参考額・国の収支の別欄・保留・測定できない）なら経済に効くと扱う。これで衆法-217-15・閣法-189-3 の分類の項目も食い違いでなくなった。閣法-180-72 は初回の抜き取りの時点では到達点が参考額だった。訂正は今の台帳に対する判定。
- 閣法-213-35：附則で修学支援の対象に専攻科の学生を加えるので「経済に効く」。初回の裁定は理由の節だけを見ていた。
- 閣法-221-52：国以外の主宰者に保険契約などを義務付け、負担金・納付金を課すので「経済に効く」。
- 閣法-180-38：延長しなければ国庫補助と起債の特例が止まるので「経済に効く」。類型は定型改正。
- 閣法-213-45：大正11年の法律の全部改正なので「実質改正」。
- 衆法-217-15：期限の置換と、延長のたびに付く経過措置だけなので「定型改正」。

## 限界

- 読み手も裁定も AI で、誤りうる。条文の後半や附則を読めていない行がある（各行の「読めなかった資料」）。
- サイトの値は6本だけ直した。抜き取っていない法律に同じ型の誤りが残る。型ごとの候補の数は `data/derived/error-type-check-v1/`（候補は誤りの疑いで、確定は一次資料の読み直しが要る）。
- 照合（`scripts/compare_verification.py`）は今も台帳の「分類」と比べる。初回の判定表を変えないため直していない。次に抜き取り検証をするときは、到達点で読む規則（`resolve_sample_failures.site_is_institutional`）に合わせる。
