# 抜き取り検証の2回目（新しい標本、2026-11-19）

初回（2026-10-30、種 20261030、118本、`docs/評価の独立検証.md`）とは別の法律を新しく抜き取り、同じ方式（サイトの値を見せない2系統の独立判定）で検証し直した記録。リリース前レビューの指摘13（「不合格のまま0」は新しい抜き取りでやり直したものではない）に答える。

## 結論（数え方の定義つき）

- **定義**：合格＝2系統の独立判定が一致した項目（類型・経済に効くか。額のある法律は分野、参考額は範囲も）が、すべてサイトの値と合う。2系統が割れた項目は、裁定者が一次資料で決めた値で比べる。**裁定が2系統の一致を覆した項目は、独立の確認（rulings.json の「確認」）が無ければ割れ（保留）にして、合格にも不合格にも数えない**（設計決定0007：採るのは2系統が一致した値）。サイトの「制度だけ」は到達点で読む（`resolve_sample_failures.site_is_institutional`）。
- **109本中、合格 39・不合格 60・割れ（保留）10**（不合格率 55%、95%区間 46〜64%、Wilson）。割れの10本は、Sonnet の裁定だけが2系統の一致（経済に効く・類型・分野）を覆してサイト側に付いた法律で、独立の確認待ち。
- 不合格 60本のうち、**範囲だけ**（参考額は産業全体の差で、法律の範囲に合わせていない＝初回と同じ仕組みの原因）は 11本。**サイトの値そのものの誤り（類型・経済に効くか・分野）は 49本**（45%、95%区間 36〜54%）。
- 決着（`resolutions.csv`、今の台帳のサイトの値で判定し直したもの。2026-11-19 夜、main 53a183b 取り込み後）：**サイトの訂正で合格 10本**（別スレッドの訂正表で値が直った）、**参考に下げた 14本**（範囲だけ。類型が直って範囲だけ残ったものを含む）、**訂正候補に回した 35本**（うち額のある 24本は直るまで額を参考に下げた。額の無い評価対象外は標本1と同じく下げない）、**独立の確認待ち 11本**（割れ10本と、今のサイトの値では割れになる不合格1本）。訂正候補は `correction-candidates.csv`（経済に効くか 19、分野 14、類型 9 項目）。決着の無い不合格・割れは 0本。
- **台帳への組み込み**：`build_evaluation_ledger.py` が標本2の法律を、今のサイトの値で `resample_verification.ledger_state` により判定し直す。額のある不合格は「参考に下げた」（初回と同じ `evaluation_rules.amount_demoted` の規則。額の無い評価対象外は下げない）、額の無い不合格は「抜き取り検証で不合格」（訂正待ち）。公開ランキングは `evaluation_rules.sample2_failures` で参考に下げる。台帳と同じ `build_evaluation_ledger.sample2_states` で今の入力から判定し直すので、ledger.csv の作り直しの順に左右されない。`verdicts.csv` は裁定のあとの記録で、`compare` は `--force` なしでは上書きしない（作り直しは記録した時点のサイトの値で判定し直す）。#229 の暫定表 `interim-holds.csv` の3本（衆法-189-20・閣法-193-61・閣法-196-2）はこの仕組みに移して表を消した。
- **完了の条件3**（`check_design_consistency.py`）は標本1と標本2を別々に数える。今は**未達**：標本2で判定なし（割れ・独立の確認待ち）10本、台帳で「抜き取り検証で不合格」のまま 20本（額の無い法律。サイトの値の訂正待ちと、確認待ち）。訂正が入って台帳を作り直すと減る。

## 手順と記録

1. 一次資料：`python3 scripts/resample_verification.py fetch`。衆議院の議案本文（`fetch_law_source.py honbun`）と国会会議録（題名＋提案、その回次）を取り、`.local/sample-v2/sources/{id}.txt` に1本1ファイルで置いた（Git には入れない。原資料は `fetch_law_source.py` が `.local/external-materials/` に観測時刻つきで登録）。109本とも議案本文を取れた。
2. 独立判定：1本につき2系統（計 218件）。モデルは Haiku（effort medium）、指示文は `prompt-v2.md`（版 v2）。サイトの値・台帳・初回の判定は見せない。系統Aは議案本文を先に、系統Bは会議録を先に読む。結果は `lineA.json`・`lineB.json`（判定、理由、原文の引用、読めた URL、読めなかった資料、確信）。確信は 高 144件・中 74件・低 0件。
3. 突き合わせ：`python3 scripts/resample_verification.py compare` → `verdicts.csv`（サイトの値も並べる）。
4. 裁定：サイトと食い違った項目か、2系統が割れた項目がある 69本を、Sonnet（effort medium、指示文 `prompt-adjudicate-v1.md`）が一次資料で裁定した。裁定者にはサイトの値と2系統の判定を両方見せる。Sonnet の裁定に入らなかった割れ 7項目（範囲 5本、類型 1本、経済に効くか 1本）は、このスレッドの Opus が裁定した。結果は `rulings.json`（項目・値・正しかった側・理由・引用・裁定者）。項目単位で、読み手が正しかった 64、サイトが正しかった 26。うち13項目（11本）は、2系統が一致していたのを裁定だけがサイト側に覆したもので、上の規則で保留にした。
5. 決着：`python3 scripts/resample_verification.py resolve` → `resolutions.csv`（原因は裁定後の記録の食い違い、決着と「今の食い違い」は今の台帳の値で判定し直したもの）と `correction-candidates.csv`（まだ合わない項目だけ。`corrections.csv` と同じ列。分野の行は今の `corrections.csv` では読めない項目）。規則はスクリプトの `cmd_resolve` にある（AI は呼ばない）。サイトの値が変わったら `build_evaluation_ledger.py build` → `resample_verification.py resolve` → `report` の順に回す。
6. 集計：`python3 scripts/resample_verification.py report` → `result.json`。

検査：`tests/test_resample_verification.py`（標本が記録した種で作れること、初回と重ならないこと、`verdicts.csv` が2系統と裁定から機械的に出ること、不合格のすべてに決着があること）。

## 初回の突き合わせとの違い

- 経済に効くかは、振り分けの分類でなく到達点で読む（初回の読み直し `../reverification-v1/README.md` で決めた規則）。
- 範囲は参考額（産業全体の差）だけに当てる。個別の額（因果の鎖）は法律ごとの推定なので範囲を問わない（初回は個別の額にも当てていた）。
- 分野が「コロナ対応」の参考額は、産業ではなく支出の費用便益の群（曝露ランキングからも除く）なので、分野と範囲を照合しない。

## 気づいたこと（この記録の範囲の外）

- **曝露ランキングへの影響**：曝露ランキングは `macro-v1/macro.csv` の産業で法律を群に入れる（`app/src/exposure-inputs.ts`）。参考額の法律の「経済に効くか」の誤り（標本の参考額 58本中 13本が一次資料では「制度のみ」）と分野の誤り（同 12本）は、額ではなく**群の割り当て**を通じて議員の曝露に入る。参考額を「参考」に下げても曝露ランキングからは外れない。
- 類型の誤りは、値が空の 11本を除く 13項目のうち 11項目が、定型改正・組織手続とされた法律が実際には中身を変えていた（実質改正・新規）向き。

## 限界

- 読み手は Haiku、裁定は Sonnet と Opus で、どれも誤りうる。議案本文は先頭 6,000字と理由までで、後半の条文や附則を読めていない行がある（各行の「読めなかった資料」）。
- 109本は層別の抜き取りで、層の大きさに比例しない（小さい層は最低3本）。不合格率は標本の率で、母集団の率の推定ではない。

## 独立の確認（2026-11-20）

保留だった 15本（判定なし10本と、今のサイトの値で割れになる5本）を、Opus が盲検（サイトの値・2系統・裁定を見せない）で一次資料（議案本文の全体と会議録）から判定した。記録は `rulings.json` の各法律の「確認の記録」（値・理由・引用・出典URL・確信・確認者）。指示は `prompt-v2.md` の項目の定義と同じ。

- 裁定が2系統の一致を覆していた項目：Opus が裁定と同じ値 → 「確認」に入れて裁定を採る（7項目：閣法-159-3 類型・経済に効くか、閣法-168-9 類型、閣法-195-6 類型、閣法-221-1 経済に効くか、閣法-186-66 類型）。Opus が2系統と同じ値 → 裁定を採らず2系統の値に戻す（6項目：閣法-168-9・衆法-166-7・閣法-142-13・閣法-198-42・閣法-195-4 の経済に効くか、閣法-166-23 の分野）。三者が割れた項目は無い。
- 2系統が割れて裁定の無かった項目（範囲・分野など7項目）：盲検の Opus の値を裁定として置いた（裁定者 claude-opus（盲検））。
- 2系統に戻した6項目のサイトの値は訂正表（`primary-source-corrections-v1/sample-v2-candidates.csv` に7行）で直した。閣法-211-46（経済に効くか）は、制度と読んだ判断が本法に懸かるとして判定不能だったので、Opus が本法・附則まで読み（`primary-source-corrections-v1/sample-v2-rulings.json` の「本法まで読んだ」）、制度に決めた。
- 結果：標本2の判定なし 0、不合格のまま 0（完了の条件3 達成）。
