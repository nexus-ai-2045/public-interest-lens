# 当て直しの読み手への指示（版 v1、2026-11-19）

測る側の法律（到達点が評価対象外でない法律）の類型・経済に効くか・主な産業分野を、題名ではなく一次資料から決め直すための指示。
読み手にはサイトの値も、前の振り分けの判定も見せない（題名と資料のファイルだけを渡す）。

定義の正本：類型と経済に効くかは `../evaluation-ledger-v1/reverification-v1/prompt-v1.md`（読み直しの指示文、版 v1）と同じ文言。試走（`pilot/`）はこの版で読んだ。後の版は `prompt-v2.md`。
主な産業分野は抜き取り検証2回目の指示文（`../evaluation-ledger-v1/sample-v2/prompt-v2.md`、版 v2、PR #223）の19区分と同じ。定義を変えるときは、正本を先に直してから、この版を上げる。

## 役割

あなたは法律1本の読み手です。次の法律を一次資料で読み、3項目を判定してください。推測で埋めず、読めた資料に書いてあることだけで決めます。

- 法律の ID：{id}
- 題名：{title}
- 資料のファイル：`{source}`（衆議院の議案本文と、国会会議録の検索結果）
- 読む順番：{order}
  - 系統A：議案本文（理由と条文）を先に読み、会議録で補う。
  - 系統B：会議録（提案理由の説明・委員長報告）を先に読み、議案本文で補う。
- 足りなければ `python3 scripts/fetch_law_source.py url <URL>` か `python3 scripts/fetch_law_source.py kokkai "語" 回次` で読んでよい（3回まで）。「取得できない」と出たら読めなかったと記録する。読めたふりをしない。ほかのファイルは読まない・書き換えない。

## 判定する項目と定義

1. 類型（1つ選ぶ）
   - 新規：新しい法律を定める。
   - 実質改正：すでにある法律の中身（対象、要件、税率、給付、規制、罰則）を変える。税法の年度ごとの改正は税率や対象を変えうるので、ここに入る。
   - 定型改正：期限（有効期限・適用期限）の延長だけ、または毎年くり返す決まった形の改正で、中身の枠組みを変えない。
   - 組織手続：組織の設置・改組、ほかの法律の施行に伴う整備、名称や手続の整理だけ。
   - 判定不能：資料が読めず決められない。
2. 経済に効くか（1つ選ぶ）
   - 経済に効く：事業者や家計の費用・価格・税負担、補助や給付の額、規制の強さ、市場への参入を、この法律が実際に変える（国の補助や特例を続ける延長も、続けなければ無くなるお金が動くなら含む）。
   - 制度のみ：組織・手続・名称・理念・計画づくり・努力義務・配慮規定など。この法律だけでは経済の量が動かない。
   - 判定不能：資料が読めず決められない。条文や附則を読めないまま「制度のみ」としない。
3. 主な産業分野（1つ選ぶ）：農林水産、労働市場、金融、医療・福祉、交通・移動、教育、通信・ネット、専門サービス・研究開発、文化・娯楽・生活サービス、エネルギー、行政のデジタル化、建設、製造業、住宅・不動産、商業、宿泊・観光、半導体・電子、鉱業・採石、経済全体（産業を特定できない）
   - 「経済全体（産業を特定できない）」は、資料を読んでも特定の産業に向かないと言えるときだけ選ぶ（全体の税、手続、理念など）。決め手が無いから選ぶ、はしない。迷ったら最も効く産業を選び、理由に迷いを書く。

## 出力

次の JSON だけを、ファイル `{out}` に書き、同じ内容を最後の返答にも出す。ほかのファイルは作らない。

```json
{
  "id": "{id}",
  "系統": "{line}",
  "何をする": "この法律がすること（60字以内）",
  "類型": "新規|実質改正|定型改正|組織手続|判定不能",
  "類型の理由": "理由（80字以内）",
  "経済に効くか": "経済に効く|制度のみ|判定不能",
  "経済の理由": "理由（80字以内）",
  "主な産業分野": "上の19区分のどれか",
  "分野の理由": "理由（60字以内）",
  "引用": ["資料の原文をそのまま20〜80字で抜いたもの（2つまで）"],
  "出典URL": ["実際に読めた URL"],
  "読めなかった資料": ["読めなかった資料と理由。無ければ空"],
  "確信": "高|中|低"
}
```

確信の目安：議案本文の理由と条文の両方を読めたら高、どちらか片方なら中、会議録の一部や題名だけなら低。

## 運用（scripts/primary_triage.py）

- モデル：Haiku（effort medium）。1本1件、系統ごとに別の読み手。
- 次のどれかに当たる項目は、Sonnet が `prompt-adjudicate-v1.md` で裁定する：2系統が割れた／どちらかが判定不能／どちらかの確信が低／2系統が一致してもサイトの値と違う（値を変える）。
- 決めた値は `labels.csv`（`../primary-source-corrections-v1/corrections.csv` と同じ列）に、判定者・指示文の版・記録の場所と一緒に書く。
