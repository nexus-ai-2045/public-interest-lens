# benefit-v1（規制の便益を測り、損失額と組み合わせて公開の可否を決める）

`loss-v1` の15本に、判定ルール `benefit-rule-v1.2`（`app/src/benefit-rule.ts`。v1 からの変更は末尾の「改定履歴」）をかけます。提案は `docs/提案/便益ルール-v1.md`（未承認）で、下の「既定」は提案 4 の推奨をそのまま入れたものです。**人が上書きできます**（上書きしたら版を上げて出し直す）。

**この段階は法律だけを扱います。** 人物・採決・役職のデータは読みません。

## 既定（人が決めること3つ。いまは推奨の既定）

| # | 既定 | 実装 |
|---|---|---|
| 既定1 | 「検出されず」（測れたが差が出ない）は便益0とみなし、表示は「便益は検出されず」 | `measureBenefit` が `yen=0`、`stateLabel` が表示の文言 |
| 既定2 | 損失額の窓が2020〜2022年と重なれば2019年で切る。開始後が2年以上残り、切った窓で impact-rule-v1 の段階と向き、loss-rule-v1 の額の向きが元と同じときだけ、切った額を公開の候補にする。そうでなければ公開不可（理由「コロナ期と分離できない」）。2023年以降はつながない | `judgeCovidSeparation`、`rejudgeImpact`（`app/src/benefit-batch.ts`） |
| 既定3 | 円への換算は公的機関が公表した単価だけ（PIO-NET の平均既支払金額など）。単価の無い種類（金融の安定・犯罪・プライバシー・環境など）は、検出されれば「検出・未換算」で公開不可 | `BenefitOption.unit`（無ければ null） |

## 入力

| 入力 | 使い方 |
|---|---|
| `data/derived/impact-v1/impact.csv` → `loss-v1` と同じ処理 | 対象の15本と、損失額（`loss-rule-v1`） |
| `data/acquired/law-purposes/purposes.csv` | 第1条の原文。改正対象ごとに施行時の版を使い、無ければ現行の版を使って印を付ける |
| `data/acquired/benefit-data/*.csv` | 便益の指標（いまは司法統計の破産新受件数だけが指標の候補に入る。下の 3） |
| `loss-v1`・`impact-v1` と同じ取得済みの統計 | 新型コロナの窓の再判定 |

インターネットからは何も取っていません。

## 再実行

```sh
cd app && node scripts/run-benefit-v1.mjs   # Node 22.18 以降
```

出力：`data/derived/benefit-v1/classification.csv`（目的の分類の2系統）、`agreement.csv`（系統1と系統2の一致）、`benefit.csv`（種類ごとの便益の状態。v1.1 から未測定の行に「未測定の符号」の列）、`data/derived/publish-v1/publish.csv`（法律ごとの公開の判定。v1.1 から「側」の列）。`loss-v1/loss.csv` は変えていません。テストは `app/src/benefit-rule.test.ts`（人工データ）。

## 方法

### 1. 目的の分類（2系統、`app/src/benefit-classification.ts`）

- **系統A**：語の対応表（`RULES_A`）を第1条に機械的に当てる。他の法律の題名の引用（「…法（昭和…号）」）と決まり文句の「公共の福祉」は先に除く。法律ごとの調整はしない。
- **系統B**：第1条を読み、直接の目的（「…により…を図り」）と最終の目的（「もって…目的とする」）から種類を付けた読み（`READINGS_B`、引用付き）。「…に鑑み」の背景は目的に数えず、税・交付金・財源の仕組みを設けるなら「移転」を付ける方針。系統Aの結果を見る前に書いた。
- 2系統の種類の集合が一致したものだけ使う。一致しなければ「目的の分類：未測定（保留）」で公開不可。第1条に目的の記述が無い場合も同じ。
- 向きの矛盾（目的が損失額の指標を抑える）も2系統で付け、一致して「抑える」なら R2。
- 種類は提案 2-4 の対応表に、`経済（付加価値の外）`（海外所得）と `移転` を加えたもの。表に無い種類は `対応表外（…）` で、指標と比較群が固定されていないので未測定。
- **限界**：設計決定0007は独立した AI 2系統を求めるが、ここでは同じ AI が同じセッションで2つの方法（語の表と読み）を書いた。独立性は限られる。独立した系統（別のモデル・別のセッション）で置き換えられるよう、系統Bは表の形で外に出してある。
- **2系統目（2026-10-17 追加）**：上の系統A・Bの一致を「系統1」とし、別のセッションが系統1を見ずに付けた「系統2」（`data/derived/benefit-v1-line2/`）と種類の集合・向きの矛盾が一致したものだけ採用する。一致しない・系統2が無いものは保留（`app/src/line-agreement.ts`、一致表は `agreement.csv`）。結果は `docs/reports/adr0007-line2.md`。

### 2. 便益の状態（`measureBenefit`）

| 状態 | 条件 | `regulationBenefitYen` |
|---|---|---|
| 内包 | `経済（内包）`。`移転` も便益に数えないので同じ扱い（0） | 0 |
| 円換算済み | impact-rule-v1 で段階1以上、公的な単価あり。差の件数×単価を損失額と同じ年数だけ足す | その額 |
| 検出されず | impact-rule-v1 で効果は計算できたが段階が付かない | 0（既定1） |
| 検出・未換算 | 段階1以上だが公的な単価なし | null |
| 未測定 | 原文なし、2系統の不一致、系列なし、比較群なし、期間不足 | null |

- 便益の指標は件数（実測値）を開始前最後の年=100にそろえ、`judgeImpact`（`app/src/impact-rule.ts`、経済全体の指標なし）にそのままかける。判定の条件は損失額の側と同じ。
- 円換算の反実仮想は「比較の指数＋開始前の差の平均」。便益の幅は単価が1つなので点（low=median=high）。
- 同じ系列を指す種類は1法律の中で1回だけ数え、法律をまたいで同じ系列・重なる窓のものは「便益グループ」にまとめる（足さない）。

### 3. 種類ごとの指標（`BENEFIT_SOURCES`、結果を見る前に固定）

| 種類 | 指標の候補 | 単価 | いまの結果 |
|---|---|---|---|
| 消費者保護 | 司法統計 破産新受件数「自然人」対「法人・その他」（2005〜） | なし | 対象の法律（2000〜2001年施行）は開始前が0年で未測定。PIO-NET の分類別は2015〜2021年度の上位25位だけで連続せず、候補に入れていない |
| 金融の安定 | なし（金融庁の全国銀行は比較群なし、預金保険機構の年次の破綻件数は未取得） | なし | 未測定 |
| 安全（犯罪） | なし（警察庁 D9・D10 は未取得） | なし | 未測定 |
| 経済（付加価値の外） | なし（日本銀行 国際収支 D11 は未取得） | — | 未測定 |
| 安全（事故）・プライバシー・環境 | なし | なし | 該当なし |

### 4. 公開の判定（`decidePublication`、提案 3-3）

上から順に当て、最初に当たった行で決めます。

| 行 | 条件 | 結果 |
|---|---|---|
| R1 | 参考の行（貸出残高を多いほど良いとみなす機械的仮定）、または loss-rule-v1 が保留 | 公開不可 |
| R2 | 向きの矛盾（2系統が一致） | 保留 |
| R3 | 窓が2020〜2022年と重なり、既定2で分離できない | 公開不可（コロナ期と分離できない） |
| R4 | 便益のどれかが未測定・検出・未換算。**ただし v1.1**：影響段階が貢献で、測った便益だけで組んだ純額の中央値が便益の側（負）であり、未測定がすべて「加算のみ」（下の 5）なら止めず、R5・R6 へ進む | 公開不可（便益を差し引けない）。例外を通った行は額を「下限（未測定の便益あり）」として出す |
| R5 | 純額の幅（下限＝損失の下限−便益の上限、上限＝損失の上限−便益の下限）が0をまたぐ | 公開不可 |
| R6 | それ以外 | 公開可（公開の候補。実際の公開は人が一括で承認する） |

R4 を通った行だけ、便益の合計（下限で出す行は、測った便益だけの合計）を `loss-rule-v1` の `regulationBenefitYen` に渡し、`publishable=true` になることを確かめてから R5・R6 を当てます（`loss-rule.ts` は変えていない）。

### 5. 未測定の符号（v1.1、`UNMEASURED_SIGN`・`unmeasuredSign`、種類ごとに事前に固定）

| 種類 | 符号 | 理由 |
|---|---|---|
| 安全（犯罪）・安全（事故）・プライバシー・環境 | 加算のみ | 指標は防いだ被害の件数・量だけで、費用の項目を同じ種類に含まない |
| 消費者保護 | 減らしうる | 供給・取引の制限で、消費者が使える商品・融資が減る面（費用）を含む |
| 金融の安定 | 減らしうる | 貸出の抑制や救済の期待（モラルハザード）で破綻が増える向きもありうる |
| 経済（付加価値の外） | 減らしうる | 海外の出資先からの所得は出資の損失で負になりうる。出資に使った資金の機会費用も損失額の系列の外 |
| 対応表外（安全保障） | 減らしうる（v1.2 の例外あり） | 指標・比較群・向きが事前に固定されていない。ただし貢献の側の未測定で、第1条の原文に「安全保障」か「セキュリティ」を含むときは加算のみ（v1.2） |
| 対応表外（…）・目的の分類（保留） | 減らしうる | 指標・比較群・向きが事前に固定されていない |

- 「加算のみ」の種類でも、悪化の向きで検出された（検出・未換算・悪化）ものと、円換算の向きが判定と食い違ったものは「減らしうる」。
- 損失の側（悪影響）と向きなしの法律には例外を当てない（v1 と同じく、未測定があれば R4）。
- 表の当てはめは AI の解釈で、評価方法として人の確認が要る。
- 影響段階1の法律（確かさ「低」）は、参考ではなく額として R1〜R6 に通します（R1 の参考は貸出残高だけ）。公開可になれば `publish.csv` の「確かさ」に `低（段階1：経済全体の指標で未確認）` が付き、理由にも書きます。議員への配分には使いません。
- `publish.csv` の「確かさ」列は `loss.csv` と同じ（高＝段階3、中＝段階2、低＝段階1、参考＝貸出残高）。

### 6. 側の表示（v1.1）

`publish.csv` の「側」は impact-rule-v1 の影響段階の向き（`impact.csv` の「向き」）から付けます：貢献＝`国士側（貢献）`、悪影響＝`国賊側（悪影響）`、無し＝`保留（向きなし）`。**法律についての表示で、人物には付けません。** 公開可否とは別の列で、公開不可の行にも付きます。

## 結果（15本）

| 行 | 本数 | 法律 |
|---|---|---|
| R1 | 10 | 貸出残高（参考）7本、通信の loss-rule-v1 保留3本 |
| R3 | 3 | 衆法-189-20（切った窓で段階1・貢献に変わる）、閣法-196-2（開始後1年）、閣法-196-4（切った窓で保留） |
| R4 | 2 | 衆法-186-35（安全（犯罪）は加算のみだが、対応表外（安全保障）が減らしうる）、閣法-189-27（経済（付加価値の外）が減らしうる）。どちらも既定2は通り、便益の側だが、v1.1 の例外に当たらない |
| R5・R6 | 0 | — |

公開可は0本です（v1.1 でも変わらず。下の改定履歴）。目的の分類の2系統の一致は15本中12本（80%）。不一致は衆法-147-33（預金者の保護を消費者保護にも数えるか）、衆法-147-34（第1条が目的規定でない禁止規定）、閣法-196-4（「理解の増進・国際交流」を目的に数えるか）。詳しくは `docs/reports/benefit-v1.md`。

## 改定履歴

| 版 | 日付 | 変更 | 理由 |
|---|---|---|---|
| benefit-rule-v1 | 2026-10-17 | 初版（提案 `docs/提案/便益ルール-v1.md` の 3-3 の表どおり） | — |
| benefit-rule-v1.1 | 2026-10-17 | R4 だけを改定：影響段階が貢献で、測った純額が便益の側の法律では、未測定がすべて「加算のみ」（上の 5）なら公開を止めず、額を「下限（未測定の便益あり）」と表示する。便益を減らしうる未測定（費用を含む種類・符号が定まらない種類）は止める。損失の側は変えない。`publish.csv` に「側」、`benefit.csv` に「未測定の符号」の列を足した | v1 の R4 は、既に便益の側にある額に「足されても便益が増えるだけ」の未測定があっても止めていた（`docs/reports/benefit-v1.md` の設計の判断 5）。この場合、測った額は便益の下限として正しく、止める理由（一方的な数字になる）に当たらない。損失の側では未測定の便益が損失を打ち消しうるので、止めたままにする |
| benefit-rule-v1.2 | 2026-10-17 | 未測定の符号だけを改定：貢献の側（影響段階が貢献）の法律で、未測定の種類「対応表外（安全保障）」は、`data/acquired/law-purposes/purposes.csv` の第1条の原文に「安全保障」か「セキュリティ」を含むとき「加算のみ」に数える。含まなければ、損失の側・向きなしの法律、未測定でない（検出・未換算）ものは従来どおり「減らしうる」。固定の規則で法律ごとの調整はしない。判定表（R1〜R6）は変えていない | 利用者が承認した既定。防ぐ被害だけを数える目的の語が第1条にあるなら、測れても便益を増やすだけとみなす。 |

R1〜R3・R5・R6、新型コロナの窓（既定2）、2系統の分類の不一致→保留、既定1・3は変えていません。`loss-rule.ts` も変えていません。v1.1 で15本の公開の判定は1本も変わりませんでした（R4 の2本は、どちらも「減らしうる」未測定があるため）。

v1.2 で公開の判定が変わったのは衆法-186-35 の1本だけ（R4 公開不可 → R6 公開可・下限）です。振り分けv2の出力（`benefit-v1-triage-v2`・`publish-v1-triage-v2`）でも同じです。詳しくは `docs/reports/benefit-v1.md`。
