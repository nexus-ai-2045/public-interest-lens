# データベースとデータの保存方針

コード・設計・スキーマはこのリポジトリで管理します。再生成できるデータベース本体と原本は、同じものではありません。

| 対象 | 保存・配布先 |
|---|---|
| カタログの構造 | `catalog-schema.sql`。個々のデータを含まない構造定義 |
| 再生成コード | `scripts/build_readable_catalog.py`、`scripts/build_economy_snapshot.py` |
| 検証用の人工データ | 既存の`tests`と画面試験の人工入力 |
| 原本・登録記録・分析ログ | まず保管先で原文を保全します。ローカルにあることだけを理由に公開対象から除外せず、秘密情報・個人情報・利用条件で仕分けます |
| 実データの公開用データベース | 内容・出典・権利・検証状態を確認した版だけ、別承認後の配布対象 |

実データの配布には、リポジトリの履歴へ更新ごとのバイナリを追加する代わりに、同じリポジトリのリリース添付を第一候補にします。公開用の版には、スキーマ版、入力原本の照合値、生成コードのコミット、対象範囲、件数、ライセンス、既知欠落を対応付けます。リリースや外部ストレージの作成は、この方針の記載だけでは実行しません。

## 公開配布版（点数なし）

`data/distribution/` は、非公開の `.local` が無い環境でもページが読める派生物です。世界銀行の`World Development Indicators`（`CC BY 4.0`）と、金融庁サイトの短い引用（公共データ利用規約第1.0版、出典付き）だけを入れます。私的な原本パス、実在人物の点数、`GDP`損失額、責任割合は置きません。再生成は `python -m scripts.build_public_distribution --input-root data/distribution/sources/world-bank --case data/distribution/case-source.json --output-root data/distribution/generated --public-dir app/public/distribution` です。指定した版のファイルが無いときは現在版へ切り替えません。


## 公開してはいけないもの

- `policy_originals`の保存パスなど、私的なファイル位置。
- 認証情報、個人情報、秘密を含む会話や分析ログの該当部分。
- 公開・転載条件が未確認の原文や資料全文。
- 「取得済み」を「内容検証済み」「採点済み」と読み替えた情報。

公開用のデータベースは非公開版をそのまま添付せず、許可した表・列だけから別の派生物として作ります。人物の氏名や投票記録が公開資料にあることと、この製品の表示・評価を公開承認したことは別です。

## ライセンスと出典

リポジトリのソフトウェアライセンスは、第三者データの転載許諾ではありません。データごとの提供元・利用条件・引用範囲を確認し、必要な出典と利用条件を公開版へ付けます。世界銀行系列と金融庁の短い引用を使った点数なしの配布データは、上記の公開配布版に含まれます。実在人物の採点版と非公開原本の配布は未実施です。

## ローカル成果の公開分類

コード・設計・人工テスト・公開用スキーマは通常の変更として検査します。政治活動の公開データは、提供元・対象範囲・時期・権利・検証状態を照合して公開用の表・列へ投影します。開発者本人の個人情報、端末パス、認証情報は投影しません。

指摘、壁打ち、設計判断、リサーチ結果は、会話という形式だけで公開対象から除外しません。`Grok`等との会話も、個人情報・秘密情報を除き、出典・本人の判断・分析仮説・検証状態を区別して公開候補にできます。外部への送信時には、対象内容と送信先を確認します。会話の全原文を取得していない時は、取得済みとは報告しません。

生成データの更新は同じ原本と生成コードから再現できることを確認します。大きな原本や更新頻度の高いデータベースは、リポジトリ履歴へ一括追加せず、内容を確認したリリース添付と取得元・再生成手順の組合せを使います。所在が未確認の成果、転載可否が不明な資料、未統合の作業を「公開済み」と扱いません。

## 最終的にローカルへ残すもの

ローカル専用にするのは、認証情報・個人情報・端末固有設定、取り除く前の秘密を含む記録、公開や転載が認められない原文、再生成可能なキャッシュ・作業途中の状態です。利用条件が未確認の資料は、確認待ちとして一時保管します。「研究メモ」「会話」「データベース」という形式だけで永久に非公開とはしません。

公開用のコード・設計・研究結果・データは、`GitHub`のファイルまたは同じリポジトリのリリース添付から参照できる状態を目指します。ローカルの正しい原本も復旧用に保持しますが、公開可能な成果がローカルにしか存在しない状態は解消対象です。
